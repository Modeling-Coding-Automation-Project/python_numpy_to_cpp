# 固有値・逆反復の独立パラメータ試験の補足

本体は変更せず、`8e22c7b327fa4d783a0db33527cc25b5d941b8ba` と、そのコミットのサブモジュールを一時ディレクトリへ展開して実験した。結果の解釈と運用方針は `document/10_independent_numerical_parameters.md` を参照。

## 条件

調整した数値は epsilon に掛ける元の数値ではなく、判定に直接渡す最終係数である。

| 記号 | 設定箇所 | 基本グリッド |
| --- | --- | --- |
| β | GMRES の `8 * epsilon` を、一時コピー内でこの値へ置換 | `8e-7`, `8e-12`, `8e-16` |
| rtol | `relative_tolerance` | `8e-7`, `8e-12` |
| vtol | `eigenvector_tolerance` | `3.2e-6`, `3.2e-12` |
| μ | `small_value`（逆反復の相対シフト係数） | `1e-3`, `1e-6`, `1e-9` |
| η | 正の `gmres_k_decay_rate`（内側 GMRES の相対残差許容値） | `5e-3`, `1e-6`, `1e-12` |

rtol/vtol/μ/η はコンストラクタ実行後に公開メンバーへ代入し、コンストラクタで設定される epsilon 由来の既定値を置き換えた。その他の epsilon 使用箇所を一括置換していない。`division_min=1e-20`、絶対許容誤差 0、一般固有値 QR 上限 128、逆反復上限 30、内側 GMRES `K=3`, cycles=1, passes=1、Jacobi 上限 10 は固定した。

基本グリッドは 108 組。基本グリッドの μ が離れており、前回共通 `1e-7` で成功したシフトの近傍を含まないため、次の 8 組を各 β に追加した。合計 132 組を二つの数学設定・二つの型で実行した。

基本グリッドの p0〜p35 は `rtol, vtol, μ, η` の順の直積で、η が最も速く変わる。β はコンパイル時の設定である。CSV の `requested_*` は要求した係数、`relative_tolerance`, `vector_tolerance`, `shift` は型変換後に実際に格納された値である。各係数には通常の `float`/`double` の丸めがある。

既存試験と同じ 3×3 の 9 入力（通常、非正規、近接固有値二種類、重複固有値、複素共役、巡回、`1e-12`/`1e12` スケール）を使用。適用可能な一般実固有値 7 件、一般複素固有値 9 件、対称 Jacobi 6 件の計 22 件/型である。**11,616 件**を測定した。std math はホスト上の原因分離用であり、組み込み向けの採用提案ではない。

## 独立した品質判定

入力を `%a` で出力し、格納された浮動小数点入力そのものに対して NumPy binary64 の固有値を求めた。固有値誤差は全順列で対応を合わせた最大絶対差を `||A||F` で正規化したもの。固有ベクトル品質は `max ||Av-λv||2 / (||A||F ||v||2)` である。ゼロベクトルは残差無限大として失敗にする。

`quality_cases` は両指標が固定ゲート以下の件数。既定 math と std float は `2e-6`、std double は高精度動作を別途調べるため `1e-10` とした。設定した rtol/vtol には連動させない。`usable_cases` はさらに固有値の収束フラグ、および一般固有値では固有ベクトルの収束フラグも成立した件数。Jacobi には固有ベクトル専用の収束フラグがない。

固有ベクトルの正規直交性、重複固有値に対応する空間全体の階数は今回の品質ゲートの対象ではない。固有ベクトルの成分一致ではなく固有対の残差を評価している。

## 一つずつ変更したときの相互作用

- **breakdown 係数を収束許容誤差と切り離せる。** 既定 float、rtol=`8e-7`, vtol=`3.2e-6`, μ=`1e-6`, η=`5e-3`（p3）で、β を `8e-7` から `8e-12` にすると、品質合格数 22 と最大残差 `1.40850e-6` は同じだが、ベクトル収束は 4/16 から 16/16、inner 失敗は 12 から 0 へ変化した。β の変更は解の要求精度を変える操作ではない。
- **内側の収束許容誤差を厳しくするだけでは改善しない。** β=`8e-12`, rtol=`8e-7`, vtol=`3.2e-6`, μ=`3e-4` で、η を `5e-3` から `1e-6`（p36 → p37）にすると、品質は両型とも 22/22 のまま、ベクトル収束は既定 float 16→14/16、既定 double 16→15/16。近接固有値や巡回行列で inner の breakdown 後に許容誤差未達となった。相対残差を過度に厳しく要求すると、外側の固有対が十分正しくても全体の成功とは扱えなくなる。
- **シフトは小さいほど良いとは限らない。** 既定 float、β=`8e-12`, rtol=`8e-7`, vtol=`3.2e-6`, η=`5e-3` で、μ=`1e-6`（p3）は品質 22/22・最大残差 `1.40850e-6`、μ=`1e-9`（p6）は品質 16/22・最大残差 `0.527046`。近接固有値・複素共役等で問題が生じた。実際のシフトの大きさはスケールや格納精度の影響も受ける。
- **固有値と固有ベクトルの精度要求も分ける価値がある。** β=`8e-12`, vtol=`3.2e-6`, μ=`3e-4`, η=`5e-3` で、rtol=`8e-7`（p36）から `8e-9`（p38）へ変更すると、既定 double の最大固有値誤差は `5.70338e-7` から `3.00998e-7`、QR sweep 合計は 42 から 45。両型の品質と収束は全件成立した。一方、rtol=`8e-12`、μ=`1e-6`（p21）では既定 float の近接固有値 `1e-10` の 2 件が QR 上限に到達した。
- **高精度設定ではシフトをさらに小さくする利益もある。** std double、β=`8e-12`, rtol=`8e-12`, vtol=`3.2e-10`, η=`5e-3` で μ=`1e-9`（p40）→`1e-11`（p42）は品質 17→22/22、最大残差 `2.172e-10`→`2.805e-11`。p42 は既定 float 向けの値ではない。

分離して設定できることは確認できたが、数値的な相互作用がなくなるわけではない。採用時には型、数学ライブラリの精度、行列の特性、固定反復上限を含む使用条件で選ぶ必要がある。

## 資源・再現性

全出力の品質指標は有限で、一般 QR の各ケースは最大 128 sweep 以下だった。オブジェクトサイズは全パラメータで同じ（float: real 176 B / complex 264 B / Jacobi 88 B、double: 296 B / 464 B / 168 B）。これはホストでのオブジェクトサイズであり、ピークスタック計測ではない。時間計測、逆反復実行回数・内部 GMRES の総仕事量はこの試験では取得していないため、QR sweep 合計だけから全体の高速化を主張しない。

再実行は NumPy を使用できるホスト Python で次を実行する。本体・依存先の作業ツリーは編集しない。

```sh
python test_vs/algorithm_improvements/run_independent_eigen_parameters.py
```

フル実行は 6 バイナリで基本グリッドと追加プロファイルをまとめて測定する。保存済み生データは基本 6 ファイル、追加 6 ファイルに分かれるが、同じ 11,616 件に対応する。`--extras-only` は既存基本グリッドへ追加プロファイルのみを追記する補助モード。`eigen_metadata.json` にピン留めコミット、依存先コミット、コンパイラ、コンパイルフラグを記録している。
