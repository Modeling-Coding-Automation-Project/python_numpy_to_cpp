# 固有値系 EIG-1〜4 の実装・評価記録

基準: `b7faabf3bbac107d1be1462d139f4be0fa25a6b7` の固定配列構成。測定: g++ 15.2.0、C++11、`-O2 -Wall -Wextra -Werror -fstack-usage`、x86_64 Linux。実機のサイクル数・WCET・RAM最大値の証明ではない。

以下の数値と試験結果は2026-11-10の記録。2026-11-11以降は固有値計算と共有ノルムの平方根を `Base::Math::sqrt` / `Base::Math::rsqrt` に委譲し、行列側からNewton反復数を指定しない。平方根の構成変更後の現行性能を示す測定値ではない。

## 採否

| 案 | 試した内容 | 判定 |
|---|---|---|
| EIG-1 | 反射行列を作らない Householder 左右適用、列スケーリング、長さ n の反射ワーク | 採用。n=8/16で時間と記憶量を削減。n=4 float のHessenberg単体は遅くなったため、小サイズ単体の高速化とは主張しない。固有値計算全体は改善した |
| EIG-2 | active block末尾2×2のシフト、Givensによる暗黙的QR、収束時だけdeflation、総sweep予算、継続状態、8 sweepごとの例外シフト | 採用。旧方式のactive block不整合を解消し、時間・記憶量・正確さを改善。実数APIは孤立した複素対を状態通知。複素APIを優先実装し、別のFrancis二重シフトは追加しない |
| EIG-3 | 固定 cyclic Jacobi、packed三角保存、値のみ／ベクトルあり、J=2/4/8 | 選択APIとして採用。値のみでは一般QRより遅い組合せもあるため、一般QRの一律置換は不採用。ベクトルも必要な対称問題と省RAM用途で効果を確認 |
| EIG-4 | 固有残差評価、S/V/K/C/P分離、スケールに応じたシフト、GMRES失敗伝播、再呼出し時の方向再利用 | 採用。doubleでは旧逆反復が反復増加で誤差を拡大する例を改善。floatでは同じVなら常に高速・高精度とはならず、許容値とVを選ぶ必要がある |
| EIG-4追加試行 | 内側P=1/2 | 試験群では精度差が小さくP=1が高速なので既定P=1を採用。P=2はGMRESの明示的な精度設定として選択可能 |
| EIG-4追加試行 | 内側K=n/2、C=4、外側V=8 | この設定を既定にする案は不採用。n=8 doubleで固有残差約0.125、時間も増加。テンプレートInnerKは作業容量を指定するAPIとして残すが、縮小したKの収束を保証しない |

三重対角化＋QRは提案書が「両方を一度に実装する必要はない」としている比較候補なので、今回の対称専用実装はJacobiを選んだ。一般非対称の逆反復へ直交化を強制しない。対称の重複固有値にはJacobiが直交基底を直接作る。

## 互換性と設定

- `EigenSolverReal<T,M>`、`EigenSolverComplex<T,M>`、既存のsetter・getter・solve名を維持する。追加のテンプレート引数 `InnerK=M` でGMRESの固定容量を変更できる。
- `iteration_max` は従来の「各active sizeに対する上限」から「1呼出し全体のsweep枠数S」へ変更。既定は `10*M`。明示的な `set_iteration_max(5)` は全体5枠であり、従来と同一精度を意味しない。
- `iteration_max_for_eigen_vector` が外側V、`gmres_k_dimension` / `gmres_cycles` / `gmres_orthogonalization_passes` が内側の実行予算を表す。実行時のKを減らすだけではスタック容量は減らない。容量削減にはテンプレートInnerKを使う。
- `relative_tolerance` / `absolute_tolerance` はdeflation、`eigenvector_tolerance` は入力最大絶対値で規格化した固有残差、`gmres_k_decay_rate` は内側GMRESの相対残差に対応する。未設定の内側許容値には `16*sqrt(epsilon)` を用いる。
- `small_value` は相対的なシフト摂動。既定は `max(1e-6,sqrt(epsilon))`。floatで1e-6だけを使うと、固有値の丸め誤差と摂動が近く、内側GMRESが不安定になる再現例があった。利用側の指定値は保持し、実際の摂動には正の `division_min` の下限を設ける。
- `get_status()`、`eigen_values_converged()`、`eigen_vectors_converged()`、`inner_solve_failed()`、`threshold_was_adjusted()`、`get_eigenvector_residual()`を追加した。低予算の対角要素は近似値であり、未収束を成功として扱わない。実数APIの `complex_pair` 状態では返却配列を実固有値として使わず、複素APIを利用する。
- 固有値の順序と固有ベクトルの符号・位相は保証しない。既存Pythonラッパの疎固有値テストは、列優先3×1の外側配列をsortしており実際には並べ替えられていなかったため、1列の要素をsortするよう親作業で修正した。
- `EigenSolverSymmetric<T,M,ComputeVectors>` は新API。利用側が対称性を保証し、上三角を入力として使う。`ComputeVectors=false` では密な固有ベクトル領域を持たない。
- Complex版のHessenberg保存先は最初からComplex型だが、実入力を実数の反射ベクトルで左右更新する。別の実数密バッファを追加しないための選択であり、虚部はQR開始まで0である。

## 測定結果

元データは `eigen_baseline.csv`、`eigen_improved.csv`。時間は5試行の最小平均、単位µs。n=4/8は1試行40回、n=16は5回。入力は固定の直交回転Qから作る `A=Q diag(1,...,n) Qᵀ`。ホストの多重実行・周波数変動の影響があり、僅差は一般化しない。

固有値の誤差は既知の値1〜nへの一対一対応で求めた最大絶対誤差/n。基準I=10/各ブロック、新S=64/全体。予算整数の同一性ではなく、結果誤差と時間を併記する。旧方式はこの入力で値自体を誤るため、同精度での速度倍率を算出しない。

| 処理 | 型・n | 旧時間→新時間 µs | 旧誤差→新誤差 | 旧オブジェクト→新オブジェクト byte |
|---|---|---:|---:|---:|
| 実数QR固有値 | double 4 | 約5.8→1.8 | 0.25→1.0e-15 | 632→416 |
| 実数QR固有値 | double 8 | 約82→7前後 | 0.925→3.0e-15 | 2232→1216 |
| 実数QR固有値 | double 16 | 約925→31 | 0.497→4.4e-15 | 8504→4352 |
| 複素QR固有値 | double 8 | 約197→20前後 | 0.950→3.0e-15 | 4936→2304 |
| 複素QR固有値 | double 16 | 約2555→72 | 1.266→4.4e-15 | 19016→8576 |

Hessenberg単体のdouble n=16は約15.5→7.6µs。Frobeniusノルム二乗の相対差は旧6.1e-16、新9.1e-16で、丸め誤差の範囲だった。n=4 floatは約0.10→0.26µsで単体の速度改善がないが、保持量とスタックは減少し、後段を含むQR全体では改善した。

逆反復単体の比較では、QR誤差の影響を避けるため**両方に既知の固有値1〜nを設定**する。各測定は同じ初期状態をコピーし、連続呼出しによって測定中だけ精度が上がることを防ぐ。コピー時間も含む。誤差は `max ||Av-λv||/(n||v||)`。

| 型・n | 設定 | 旧時間 / 誤差 | 新時間 / 誤差 |
|---|---|---:|---:|
| double 4 | V=3 | 約3.5µs / 2.9e-5 | 約7.4µs / 1.0e-13 |
| double 16 | V=8 | 約442µs / 1.2e-4 | 約316µs / 1.7e-13 |
| float 8 | V=8、既定許容値 | 約45µs / 6.0e-7 | 約22µs / 1.4e-6 |
| float 8 | 新のみ厳しい許容値、V=8、P=1 | 比較基準は上行 | 約44µs / 6.0e-7 |

floatの既定設定は精度と時間の交換であり、同精度の主張には厳しい設定の行を使う。doubleでは内側精度を上げるとn=8の誤差を約6.6e-15まで減らせた。内側P=2はこの試験ではP=1と同程度の精度で遅いため、既定にはしなかった。

Jacobi double n=8、J=8では値のみ約12µs / 誤差6.7e-16 / 336 byte、固有ベクトルあり約13µs / 固有残差1.2e-15 / 848 byte。一般実QRは値のみ約7µsで1216 byte、さらに逆反復時間が必要になる。値のみの最短時間では一般QR、少ないRAMや対称のベクトル生成ではJacobiを選べる。J=2の値誤差は約0.005であり、低sweepの近似を高精度解と扱わない。

## スタックと制約

`eigen_stack_baseline.txt`、`eigen_stack_improved.txt` は `-fstack-usage` の関数単体の記録。全呼出し経路の最大スタックではない。

| 関数 | double n=8 旧→新 byte | double n=16 旧→新 byte |
|---|---:|---:|
| Hessenberg | 1680→160 | 6368→208 |
| 逆反復（InnerK=n） | 3120→2448 | 10096→7056 |

保持オブジェクト、入力、返却行列、呼出し先フレームは別に必要。コンパイラ最適化でフレームの分担が変わるので、sizeofと単体フレームの合計をそのままピークRAMと扱わない。

追加したヘッダに `<cmath>`、`<algorithm>`、`while`、例外、動的ワーク領域、非有限値チェックはない。反復枠は有限forで固定し、終了状態の数値更新を省略する。スケーリング後の非零分母を使い、ゼロベクトル・ゼロ回転・無効な閾値を先に処理する。微小な判別式の平方根は11個の固定正規化枠を通し、依存ライブラリのfloat初期値がdoubleの微小値で破綻しないようにした。

## 検証

- `eigen_regression.cpp`: float/double、実数・複素1×1、零行列、active blockの再現例、零予算、継続、既知の非対称スペクトル、純虚数対、巡回置換、Jacobiの直交性・固有残差・packed値専用、重複固有値、負閾値・負許容値、内側零予算、極小平方根。0 failures。
- 同試験のASan、UBSan、float-divide-by-zero sanitizerを実施し通過。
- 既存Base層の固有値・固有ベクトル試験はdouble/floatとも通過。
- `eigen_numpy_oracle.py`: NumPy 2.5.4をホスト側のみで使用。n=3/4/6の乱数行列36個、近接・重複・巡回行列9個、計45例。Complex QR S=512で全例収束、スペクトルの最大規格化誤差1.89e-15。順序による誤判定を避けるためn≤6の全順列対応で比較。

再実行は親の `run_validation.py` でC++試験・同一ソースによる基準/改善測定を行う。NumPy oracleはNumPyを用意したホストPythonで `python eigen_numpy_oracle.py --root <repository>` として実行する。任意入力・任意マイコンでの支配的な優位性は有限個のホスト測定では証明できず、入力のスケールと予算を選び、返却状態・API前後の非有限値検査を利用側で確認する。
