# 前回測定時からの性能比較における benchmark 監査

対象は前回測定相当 `879a31981d4cb99173939bd4a12df96bf8ccdf1a`、固定パラメータ化直前 `ab31b0d`、現行 `b599e8461d0a4b07aa007bc6376746744767e671`。既存 benchmark の変更は行わず、同じ source を各版のヘッダへ組み合わせる。依存先・コンパイラ・最適化・マクロ・CPU を揃える。

以下は計測方法の監査であり、速度の測定結果そのものではない。新しい時間・ピーク RAM の測定値は実行 runner の記録を参照する。

## 既存 benchmark の比較条件

3版とも新しいクラス API を含むため、既存 source の `ALGORITHM_IMPROVEMENTS` は **3版すべてで定義**する。このマクロの有無を版ごとに変えると、Eigen の予算や実行対象 API が変わる。

| source | 時間に含むもの | 時間に含まないもの | 誤差・状態の制約 |
| --- | --- | --- | --- |
| `qr_benchmark.cpp` | 毎回の solver 構築と因子分解。`full_q` は Q の展開、`apply_qt` は右辺作成・適用も含む | 通常 Householder 行の Q の展開、品質計算 | 再構成・直交性・下三角誤差を入力と同じ T で計算。float の丸め床より細かな差の評価には不向き |
| `eigen_benchmark.cpp` | Hessenberg・QR・Jacobi は既存 solver の再利用。逆反復は毎回の solver **コピー**と求解 | 再利用行のコンストラクタ。逆反復行の固有値求解。品質計算 | 収束・inner 失敗・実 QR sweep 数を出力しない。既知固有値 1..N は入力丸め前の値 |
| `lu_chol_benchmark.cpp` | `lu_default` は再因子分解＋求解、`lu_reused/cached` は右辺求解。Cholesky tuple 経路は出力と fallback の処理を含む | LU オブジェクト構築、reused/cached の因子分解。品質計算 | 格納済み A,b の long double 参照解・再構成を利用。Cholesky の失敗 bool は全行で出力しているわけではない |
| `gmres_benchmark.cpp` | legacy は互換関数全体、configured は構築済み workspace での求解 | configured のコンストラクタ、逆対角の準備。品質計算 | 誤差は製造した target への RMS。丸めた A,b の厳密解との誤差ではない。収束・breakdown・実反復数を出力しない |
| `gmres_rect_benchmark.cpp` | rect API/明示 Gram/matrix-free の各呼出し。明示行は Gram と normal RHS の構築を含む | 品質計算 | 製造した target への RMS のみ。正規方程式による条件数の増加や実残差は直接評価しない |

各行の契約を固定して版間で比較できる。一方、constructor を含む行と再利用行、Q を展開する行と因子だけの行など、異なる行を同じ処理の速度として扱わない。

## 反復数と計時の集計

- QR は寸法ごとに 12,000 / 3,000 / 700 / 100 回、3 trial の反復平均の最小値。
- Eigen は N≤8 で40回、それ以外で5回、5 trial の最小値。一般固有値の QR は64枠、逆反復は1/3/8枠。短い行では測定ノイズの相対影響が大きい。
- LU/Cholesky は事前に1回実行し、500回×5 trial の中央値。
- GMRES と矩形 GMRES は1,000回の平均を1プロセス内で取得する。

新しい runner が複数プロセスを交互に実行する場合、その外側の集計と各 source 内の集計を区別する。単一の最速値だけから数%の差を断定しない。CPU 固定は周波数、OS負荷、冷却条件を完全に固定するものではない。

## 最適化と入力の問題

QR は solver 全体のアドレスを渡す `asm volatile` と memory clobber により、全因子の書込みを保持する。Q の展開結果にも barrier がある。

他の既存 source は volatile な sink を更新し、LU/Cholesky では noinline wrapper も使っている。このため求解全体の削除を避ける意図はあるが、sink 一成分の観測だけで全状態の計算保持やループ外への移動が不可能だとまでは保証しない。実際に削除・移動されたかは生成コードで判定する必要がある。監査のみから「最適化で測定が無効」と断定しない。

GMRES は `rhs[0] += ±1e-6` で入力を交互に変える。ただし float の大きな値では加算値が ULP より小さく、入力が変化しないケースがあり得る。また足して引く操作がビット単位で元に戻るとは限らない。target は不変なので、最後の誤差はこの摂動・丸めも含む。悪条件入力の正しさは、既存の格納入力 oracle を別途使用する必要がある。

矩形の明示 Gram 行は反復内にコードがあるが、A は不変である。コンパイラが invariant な Gram 構築の一部を再利用する可能性を、source のループ位置だけで排除しない。

## Eigen の固定パラメータ化を比較する際の注意

同じ source の実行であっても、既定値を使う行の要求精度が版間で変わる。

| 係数 | epsilon 使用時 | 現行 A |
| --- | --- | --- |
| 固有値の相対収束判定 | `8 * epsilon(T)` | `8e-9` |
| 固有ベクトルの相対残差判定 | `32 * epsilon(T)` | `3.2e-6` |
| 相対シフト | `max(1e-6, sqrt(epsilon(T)))` | `3e-4` |
| 内側 GMRES の自動相対許容誤差 | `16 * sqrt(epsilon(T))` | `5e-3` |
| GMRES breakdown の相対係数 β | `8 * epsilon(T)` | `8e-12` |

値の式は前回版の既定処理を説明したもので、依存先の平方根近似による丸めを含む実測値ではない。

旧 float の固有値許容誤差は約 `9.54e-7` なので現行の `8e-9` は厳しい。旧 double は約 `1.78e-15` なので現行は緩い。float で QR の仕事量が増え、double で減る可能性がある。逆反復も許容誤差・シフト・breakdown が同時に変わるため、実反復数を単純には予測できない。最大反復予算と実際に行った演算量は区別する。

既存 `inverse_strict_p1/p2` 行は vtol を epsilon、inner 許容誤差を sqrt(epsilon) に明示しているが、シフトは各版の既定値を使う。この行も完全な同一設定比較ではない。また厳しい vtol は既定数学ライブラリの精度床を下回り得るので、未収束の時間を成功した同精度求解の時間として扱わない。

公平な確認には次の二種類が必要である。

1. **既定値同士の比較**：利用者が同じ API を使ったときの時間・最終誤差・収束状態の変化を評価する。
2. **公開パラメータを揃えた比較**：rtol/vtol/shift/inner 許容誤差を直接指定し、最大予算・分母保護を固定する。ただし β は公開設定ではないため版差が残る。β の影響が疑われる結果では、一時コピーだけを変更した追加診断が必要になる。

いずれも、残差や真値誤差を収束フラグとは独立に確認する。フラグが変わっただけの差を精度向上・低下と同一視しない。逆に残差が小さくても inner 失敗を成功と読み替えない。

## 新しい `eigen_performance_probe.cpp`

この補助 source は3版すべての一般実・複素 Eigen API でコンパイルする。既存 benchmark は変更しない。`*_benchmark.cpp` の自動列挙に含めない名前にしてある。

入力は厳密に表現できる対角2・隣接要素-1の三重対角行列 L と、対角 D が1と2で交互になる `D L D^-1`。固有値は格納済み入力そのものに対して `2 - 2 cos(kπ/(N+1))` である。ホストの long double の三角関数を参照に用い、既存 benchmark の「入力丸め前の1..N」との比較を補う。N=4/8/16、float/double、real/complex の組合せで測定する。

| profile | rtol | vtol | shift | inner 許容誤差 |
| --- | --- | --- | --- | --- |
| `defaults` | 各版の既定値 | 各版の既定値 | 各版の既定値 | 自動設定のまま |
| `explicit_a` | `8e-9` | `3.2e-6` | `3e-4` | `5e-3` |
| `explicit_b` | `8e-12` | `3.2e-10` | `1e-11` | `5e-3` |

すべて QR 上限64、逆反復上限30、K=N、cycles=1、passes=1、division_min=`1e-20`、絶対許容誤差0。公開パラメータは構築後に直接設定する。`explicit_b` は高精度診断であり、すべての型・数学設定で収束すると仮定しない。

`values_reuse` は構築済み solver を再利用し固有値を求める。`values_vectors_fresh` は毎回 constructor と設定を含めて固有値・ベクトルを求め、warm start を用いない。入力と全solver状態をmemory barrierに渡し、毎回の計算を保持する。品質計算とprintfは計時外である。

引数なしではN=4/8/16に対して80/30/8回。任意の第1引数で全行の反復回数を上書きできる。各行はwarmup1回の後、3 trial の反復平均の中央値を返す。1プロセス144行。

```sh
./eigen_performance_probe 8
```

CSV の identity は `algorithm,type,n,fixture,profile,stage`、時間は `ns`。`value_error` は既知固有値に対応を付けた最大誤差 / `||A||F`、`vector_residual` は long double で再計算した `max ||Av-λv||2 / (||A||F ||v||2)`。values-only 行の residual は未計算を示す -1。収束フラグ、inner失敗、status、実QR sweep、sizeof、反復設定と公開パラメータの型変換後の値も出力する。`inner_requested=0` は各版の自動設定を意味し、実効値0ではない。

`finite_output` は出力品質指標が有限かを示す。収束していなくても有限な近似解を返すことがあるため、この列だけで成功とは判定しない。

## RAM に関する解釈

`sizeof(solver)` は入力・返却値・局所ワーク・呼出し先フレームを含まない。`.su` は1関数のフレームであり、そのままコールチェーンのピークではない。benchmark 内には計測や品質判定用の別オブジェクト・コピーが同時に生存する。

特に新しい Eigen probe のフレームには入力、再利用solver、結果検証用solver、残差用のコピーがある。このフレームをライブラリ単独のピークRAMとして用いない。薄い専用wrapperと呼出し先フレーム、または実行中のスタック計測を組み合わせて比較する。ホストで得たピークも対象MCUの割込みを含む最悪スタックとは異なる。
