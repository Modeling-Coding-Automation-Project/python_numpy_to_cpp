# 組み込み向け行列計算アルゴリズムの改善案

調査日: 2026-11-09

対象リビジョン: `5ef4ecc`

参照サブモジュール: `base_utility_cpp` = `6d4807d`、`python_math_to_cpp` = `fc93257`

本書は行列計算アルゴリズムの実装に先立つ提案書であり、対象5ファイルのアルゴリズム改善は未実装である。上記リビジョンの実装を読み、一部の問題を小型のC++11プログラムで再現した。その後、使用条件を見直して `<algorithm>` を許可し、依存ライブラリの `base_math_arithmetic.hpp` は既定設定で `<cmath>` をインクルードしないよう修正した。以下の計算量・記憶量はコードとアルゴリズムからの見積もりであり、改善後の実機測定結果ではない。

## 1. 対象と推奨方針

| 対象 | 現行方式 | 優先する改善 |
|---|---|---|
| [QR](../base_matrix/base_matrix_qr_decomposition.hpp) | Givens回転。密なQとRを保持。疎入力もRを密化 | 再実行・fill-in処理の修正、密行列向けのコンパクトHouseholder QR、Qを生成しない経路 |
| [固有値・固有ベクトル](../base_matrix/base_matrix_eigen_solver.hpp) | 明示的な反射行列によるHessenberg化、シフト付きQR、GMRESを使う逆反復 | 反射の直接適用、active blockに対する暗黙的QR、収束を確認したdeflation、実対称専用経路 |
| [LU](../base_matrix/base_matrix_lu_decomposition.hpp) | 微小対角時だけ行交換するLU。LとUを別々に保持 | 部分ピボット選択、因子・行列式の修正、LUの単一配列保存、固定回数の反復改善 |
| [Cholesky](../base_matrix/base_matrix_cholesky_decomposition.hpp) | 内積型の上三角分解。疎入力は密化 | 全除算の保護、三角領域でのin-place更新、SPD用途のLDLᵀを選択肢として追加 |
| [逆行列・線形方程式](../base_matrix/base_matrix_inverse.hpp) | MGS直交化とGivens回転によるGMRES | GMRESを維持し、複素回転・breakdown処理・作業領域・反復予算を改善 |

`base_matrix_inverse.hpp` ではGMRES以外の解法を提案しない。既存の対角逆行列関数も今回の改善対象から外す。固定ループや条件分岐をテンプレートメタプログラミングで展開する案は扱わない。以下で使うサイズテンプレートは、固定容量を決めるためのものである。

推奨順序は、**数値的な正しさと制約適合 → 不要な行列の除去 → アルゴリズムの選択肢追加 → 実機で設定を選定**とする。

## 2. 全案に共通する設計条件

### 2.1 C++11・固定メモリ・既存構造

- `Base::Matrix` 名前空間、ヘッダオンリー、`template <typename T, std::size_t ...>`、`inline`、既存の `solve` / `get_*` / `set_*` の構造を踏襲する。メンバ名・コメント・インデントは各対象ファイルの規約に合わせる。
- 既存の `Matrix`、`Vector`、`std::array` で固定容量を確保する。VLA、`new`、`malloc`、動的コンテナを用いたワーク領域は使用しない。
- `<algorithm>` は使用してよい。固定範囲の初期化・コピーには既存の `std::fill` / `std::copy` 等を利用し、動的確保禁止・C++11・決定的な処理回数など、ほかの条件は維持する。
- ワーク領域はクラスまたは呼出し側が所有する。同時に必要な領域だけを保持し、段階が変われば再利用する。単にローカル配列を共有 `static` に移しても総RAMは減らず、再入可能性も失う。
- 既存APIは互換ラッパとして残し、省RAM用には出力参照・ワーク領域参照を受け取るオーバーロードを設ける。既存getterが密行列を返す場合、その出力分のRAMは必要である。
- `try` / `catch`、例外送出、`abort`、実行時assertによる停止は使わない。不適合入力・未収束は既存のboolや追加の状態値で通知する。状態通知は実行時エラーを発生させる仕組みにしない。

固定配列構成では `Matrix` は列優先の `data[col][row]` を持つ。rank-1更新などは可能な範囲で行添字を内側に置き、連続アクセスにする。これは更新順序の選択であり、テンプレート展開の提案ではない。

### 2.2 依存経路の構成と整備

`<algorithm>` のインクルードと使用は許可する。`<cmath>` を使わない組み込み構成、固定メモリなどの条件は、対象5ファイルから到達する依存ヘッダも含めて確認する。

| 項目 | 現状 | 必要な方針 |
|---|---|---|
| 動的記憶域 | `BASE_MATRIX_USE_STD_VECTOR_` で切替。現在は未定義 | 組み込み構成では未定義を必須とする |
| `<algorithm>` | `base_matrix_matrix.hpp:30` が直接include。`std::copy`、固有値計算の `std::fill` も存在 | 使用可能。禁止事項への対応としてこれらを置換・削除する必要はない |
| utilityの標準コピー | `BASE_UTILITY_USE_STD_COPY_` を定義すると `<algorithm>` に依存 | 定義してよい。固定範囲のコピーに使用でき、未定義を必須としない |
| `<cmath>` | 今回の修正後は `base_math_arithmetic.hpp` が `BASE_MATH_USE_STD_MATH_` 定義時だけinclude | 組み込み構成では `base_math_macros.hpp` の既定状態どおり標準数学マクロを未定義とする。標準数学関数を使用する構成では定義してincludeする |
| 初期値作成 | `Vector::Ones()` は固定配列構成でも一時 `std::vector` を作る | 新実装から呼ばず、固定配列へ直接書く。対象5ファイルでこの関数の呼出しは確認されず、`Matrix::ones()` と区別する |

`<cmath>` のインクルード条件は今回修正したため、これを避けるための `NEVER_USE_CMATH_BUT_REQUIRES_IEEE_754_STANDARD_` の追加定義は不要である。数学関数のアルゴリズム選択は既存マクロに従う。インクルードの有無とは別に、使用するビット操作系の実装では対象CPUのIEEE 754形式を確認する。ビルド時は対象APIの依存経路まで確認する。

### 2.3 反復回数を事前に決める

現行の `iteration_max` と途中の `break` は最大回数を制限するが、実際の反復回数は入力依存である。本案では要求を厳しく解釈し、呼出し開始前に次の回数を確定する。

| 処理 | 事前設定する予算 |
|---|---|
| QR・LU・Cholesky | 行列サイズから決まる有限の走査回数 |
| 固有値QR | 1呼出し当たりのQR sweep数 `S` |
| 対称Jacobi | 全添字対を巡回するsweep数 `J` |
| 固有ベクトル逆反復 | 外側の反復数 `V` と、内側GMRESの予算 |
| GMRES | Krylov次元 `K`、cycle数 `C`、直交化pass数 `P` |
| LUによる反復改善 | 補正回数 `R` |
| sqrt / rsqrt | 選択した実装の固定反復数 |

すべて有限の `for` で表現する。収束・失敗・breakdown後は状態フラグにより更新を停止し、残りの反復枠を消化する。active blockが縮小しても、厳密にループ回数を固定する構成では最大サイズの添字走査を保ち、対象外の計算をマスクする。無効な分母の式を評価してから結果だけを捨てる実装にはしない。

固定予算内に収束しなければ、近似値と未収束状態を返す。任意の行列について、固定回数で指定精度の解が必ず得られるとは保証しない。`continue_solving_eigen_values()` も1回当たりの追加予算を明示する。

フラグによる演算省略やCPUの分岐によってサイクル数は変わり得る。固定の反復枠と、サイクル単位の定時間実行は区別し、実機で最悪実行時間を評価する。

### 2.4 全除算の保護と数値スケーリング

1. `division_min` は型とCPU上で正の非零値として表現できる値に限定する。ゼロ・負値などの設定は入口で検出し、有効な既定値へ補正したことを状態に残す。publicメンバへ直接代入できるクラスではsetterだけでなく `solve` 側でも確認する。
2. 実数の可変分母には `Base::Utility::avoid_zero_divide(d, division_min)` を使う。同じ分母の逆数は保護後に1回だけ計算し、乗算で共有する。逆数自体が表現範囲を超えない入力スケールも必要である。
3. 分母が零・微小になる数学的意味を先に判定する。零ノルムは正規化しない。零ピボット、階数落ち、非正定値は状態として扱い、単なるクランプを正常な分解とみなさない。
4. 複素除算は `complex_divide` を基本にするが、内部の実部・虚部の二乗和はoverflowを防がない。大きさが広範囲に及ぶ経路では成分をスケーリングし、比率の分母と最後の分母の両方を保護する。`Complex<T> / T` は呼出し側で分母保護が必要である。
5. 収束判定、階数判定、分母保護の閾値を分離する。ノルム二乗に対する閾値と、ノルム・ピボットに対する閾値を同じ数値で代用しない。閾値の二乗にもunderflow対策が必要である。
6. 診断用の相対残差・スケーリング比・シフト生成・前処理の除算も対象に含める。添字計算の `/ 2` など、分母が非零定数である演算はその事実で安全性を保証する。

利用する [base_utility.hpp](../external_libraries/base_utility_cpp/base_utility/base_utility.hpp) の `avoid_zero_divide` 自体は `division_min > 0` を検証しない。また [base_math_exponential_logarithmic.hpp](../external_libraries/python_math_to_cpp/base_math/base_math_exponential_logarithmic.hpp) の `sqrt(x, division_min)` は小さい入力を閾値へ置き換えるため、`sqrt(0)` が0にならない。零ベクトル・零残差の判定は平方根より前に行う。

ノルムは最大絶対値 `s` を求め、`s == 0` を先に処理し、スケールした要素の二乗和から計算する。実数Givensでは2要素の最大絶対値で正規化すれば、sqrt/rsqrtへ渡す二乗和を通常 `[1, 2]` にできる。スケール除算も保護し、閾値未満を零とみなす場合は、その判定を記録する。元のスケールへ戻した値が型の範囲を超える入力は、値域の契約または状態通知で扱う。

既存の `sqrt_newton_method<T, LOOP_NUMBER>`、`rsqrt_newton_method<T, LOOP_NUMBER>` は精度・時間の選択に使える。ただし後者の初期値生成はfloatへの変換を含むため、doubleの全指数範囲を無条件に扱えるとはしない。必要なら正規化した入力に適用する。既存サブモジュールの反復数を選ぶだけで、新たなメタプログラミング展開は導入しない。

## 3. 性能比較に先立って修正すべき現状

以下は上記リビジョンのソース調査で見つかった問題である。最小再現は `<cmath>` のインクルード条件を修正する前に、既定マクロのまま `g++ -std=c++11 -O2` で確認した。組み込み向けの全条件を満たす構成で検証した、という意味ではない。

| 箇所 | 問題・根拠 | 改善時の要件 |
|---|---|---|
| QR `solve`、170行付近・401行付近 | Rは入力に戻すがQを単位行列へ戻さず、前回のQが残る | 呼出しごとに因子の状態を初期化する |
| 疎QR `_decompose`、450行付近 | 元のCSRの非零位置・値を基準に回転を選ぶ。回転で発生したfill-inを走査しない | 現在のR、またはfill-inを含む保証済みパターンで消去する |
| 固有値 `_wilkinson_shift`、460行付近・1033行付近 | active size `k` が縮んでも末尾の `M-2, M-1` を参照する | active block末尾の2×2からシフトを作る |
| 固有値QR、488行付近・1072行付近 | シフト対象は先頭kだがQR更新は全M。予算切れでもkを減らす | 更新範囲を一貫させ、未収束ブロックを強制的に確定しない |
| LU `_decompose`、184–201行付近 | Lの対角を1にした後にLの行全体を交換し、単位対角が崩れる | 分離保存なら既確定列だけを交換する |
| LU `get_determinant`、142行付近 | L対角の問題に加え、行交換の符号を反映しない | `det(A) = (-1)^swap_count × product(diag(U))` とする |
| Cholesky、68・84・189・205行付近 | `1 / temp_inv` に明示的な分母保護がない | reciprocal sqrtの結果に対する除算も保護する |
| 複素GMRES、1408行付近・1663行付近 | 実数用と同様に複素のcを作る一方、適用式はcを実数とするユニタリ回転の形 | 位相を考慮した複素Givensへ修正する |
| 複素GMRESの残差 | denseは `rho = abs(b_hat)^2` を `b_norm^2` で割り、sparseは `b_norm` で割る | ノルムと二乗ノルム、許容値の意味を統一する |

再現例:

- QR: `A = [[1,1],[1,0]]`。同じインスタンスで2回 `solve(A)` すると、`max|QR-A|` は初回約 `2.22e-16`、2回目 `1`。
- 疎QR: `A = [[1,1,0],[0,1,1],[1,0,1]]`。結果に `R(2,1) ≈ -0.70710678` が残り、上三角にならない。再構成だけでは検出できないので三角性も検証する。
- 固有値: `A = [[2,1,0],[1,2,0],[0,0,100]]`。正解は `{1,3,100}`。既定設定では約 `{1.7792,2.2208,100}`。active sizeが2でもシフトは約100になる。
- LU: `A = [[0,1],[1,0]]`。`get_L()` は `[[0,0],[0,1]]`、行列式は0となるが、正しい行列式は−1。この例の `solve([1,2])` は `[2,1]` を返すため、線形方程式の解まで一律に誤るとはしない。
- 複素GMRES: `A = [[i,0],[1,1]]`、`b = [1,0]`、初期値0、`decay_rate = 0`、`division_min = 1e-20`。結果は `x = [0,i]`、報告 `rho = 0` だが、実残差は `[1,-i]`。正解は `[-i,i]`。
- 対角Cholesky: `diag(0,1)` に対して約 `diag(1e-5,1)` と成功フラグが返る。零を許容する現在の対角版では、零の平方根を明示的に0とする必要がある。

## 4. QR分解の改善案

### QR-1: 密行列ではコンパクトHouseholder QRを追加する【優先度: 高】

現行Givensは各消去でRの行と、明示的Qの列を更新する。`m >= n` とすると演算量は概ね `O(m n² + m² n)`、保持量は `mn + m²` 要素である。さらに `qr_givensRotation` はQ・Rを値渡ししtupleで返すため、固定配列では行列規模のコピーが発生し得る。ムーブや最適化によって常に除去されるとは仮定しない。

密行列向けに、反射 `H = I - tau v vᵀ` を行列として作らず直接適用する方式を追加する。

1. 各列の対角以下からスケール付きノルムを求める。反射の符号は桁落ちを避ける側を選ぶ。零ベクトルには `tau = 0` を設定する。
2. 上三角にR、対角下に反射ベクトルの尾部を同じ `Matrix<T,M,N>` へ格納し、`tau` を長さNの配列へ格納する。
3. 後続列へ `a := a - tau v (vᵀ a)` を直接適用する。反射ベクトル正規化の分母は保護し、階数落ちは別途通知する。
4. `get_Q()` が必要なときだけ反射を適切な順序で適用してQを生成する。`Qᵀ b` だけ必要な用途には、Qを生成せず反射列を適用する関数を追加する。

因子のみなら演算量は `O(m n²)`、保存量は `mn + O(n)`。完全なQを実体化すれば `m²` の出力領域と生成時間が必要になる。既存クラスにQの密配列を残すだけでは省RAMにならないため、互換経路とコンパクト因子を保持する経路を分ける。

Rの取得時は下三角に格納した反射情報を零へ置き換えて出力する。既存のQRラッパが返すQ/Rの形と、Rを用いた後退代入の意味は維持する。通常の実数QRを対象とし、複素QRへ拡張する場合は転置を共役転置へ置き換えた別検証が必要である。

反射の格納方法は [LAPACK DGEQRF](https://www.netlib.org/lapack/double/dgeqrf.f) を参照できる。LAPACK自体を組み込みへ導入する提案ではない。

**トレードオフ:** 因子だけ／Qᵀ適用／明示Qの出力モードと、平方根精度を選ぶ。QRは直接分解なので、反復回数を減らして近似することを基本設定にはしない。極小の消去対象を閾値で省略する経路は、再構成誤差・直交性を測定した明示的な近似モードに限る。

### QR-2: Givensは構造化行列用に残し、更新をin-placeにする【優先度: 高】

- `qr_givensRotation` の内部コアはQ・Rを参照で更新する。既存の値返却関数を残す場合も内部コアへ委譲する。
- `solve` ごとにQを初期化する。各回転では現在のRを参照し、消去した要素を明示的に0へ設定する。
- 一般疎入力は、まず現在の密Rの必要な下三角全体を走査する方式で正しさを確保する。元の非零パターンだけを走査する最適化は採用しない。
- 上Hessenberg・帯行列などfill-inの範囲が保証される入力には、固定帯域を使った専用経路を用意できる。入力時点の疎性だけで計算量・RAMが小さくなるとは保証しない。
- 行列の同じ位置がどの回転で更新されるかを規定し、Qへの適用方向も再構成で確認する。

Givensは2要素更新で実装が比較的単純であり、構造化行列に適する。密行列・小型行列ではHouseholderとの優劣を実測で選ぶ。

## 5. 固有値・固有ベクトル計算の改善案

### EIG-1: Hessenberg化で明示的な反射行列を廃止する【優先度: 高】

現行 `_hessenberg` は `VariableSparseMatrix` の `House_` に反射を構成し、`R = House_ * R * House_` を計算する。反射の後続部分は密になり、固定配列構成の `House_` 自体にも `n²` 個の値、`n²` 個の添字、`n+1` 個のポインタがある。

各段階で反射を作り直して汎用積を行うため、密入力ではHessenberg化全体が概ね `O(n⁴)` になる。反射の左右適用を次のrank-1更新として直接行い、`O(n³)` にする。

- 左側: `A := A - tau v (vᵀ A)`。
- 右側: 左更新後のAを使い `A := A - tau (A v) vᵀ`。
- 操作対象の部分行列だけを更新し、消去した位置は0にする。左右更新で使うベクトルは順次再利用する。

Hessenberg行列 `n²` に加え、反射・積の一時領域は `O(n)`。`House_` の値と添字配列、行列積の一時オブジェクトを除去できる。現行の固有ベクトル逆反復は元の行列を使うので、その経路を保つならHessenberg変換のQを保持する必要はない。

`EigenSolverComplex` の公開入力も現状は実行列である。実行列のHessenberg化は実数のまま行い、複素演算が必要になる段階で変換する方針を維持する。一般複素入力への対応を既存機能と混同しない。

直接適用とコンパクト保存の構成は [LAPACK DGEHD2](https://netlib.org/lapack/explore-html/d6/dfb/dgehd2_8f_source.html) を参照する。

### EIG-2: active block上の暗黙的シフトQRへ変更する【優先度: 高】

現行QR sweepは局所反射を明示行列へ埋め込み、Q・Rを作り、`R Q` を計算するため、1 sweepが概ね `O(n³)`。さらに現行は最大 `n-1` 個のkにそれぞれ `iteration_max` を与えるため、全体の上限はHessenberg化と合わせ概ね `O(n⁴ + I n⁴)` になる。`I` は現在の各k当たりの反復上限である。

改善案では上Hessenberg構造を保ったまま、短いGivensまたはHouseholderを左右へ適用してbulgeを追い出す。密なQ・Rを一時生成しない。1 sweepの演算量は `O(n²)`、初期Hessenberg化とS回のsweepを合わせ `O(n³ + S n²)` になる。旧設定Iと新設定Sは意味が違うため、同じ数値で比較しない。

実装時の条件:

1. シフトはactive block末尾の2×2から計算する。
2. `|h(i,i-1)| <= abs_tol + rel_tol × (|h(i-1,i-1)| + |h(i,i)|)` 等のスケールを考慮した条件で分離を判定し、分離するときだけ下副対角を0にする。全体スケールも使って閾値の極端な偏りを防ぐ。
3. 予算が尽きても未収束ブロックを分離しない。Hessenberg行列とactive blockの状態を保存し、継続計算へ渡す。
4. 反復枠は全体でS回に固定する。複数の未収束ブロックがある場合の処理順序を固定し、block境界は固定容量の添字配列で保持する。
5. Schur形を保持する経路ではactive blockと他ブロックを結ぶ必要な領域も左右変換する。単に先頭k×kだけ更新して、全行列に対する相似変換が成立すると扱わない。
6. 1×1入力は専用の有限処理とする。現在の `M-2` のような符号なし添字の減算を小サイズで評価しない。

**実数と複素数の扱い:** 一般の実非対称行列では複素共役固有値があり、実数1値ずつのシフトでは十分ではない。実演算で進めるならFrancis二重シフトと実Schur形の2×2ブロック処理が候補になる。`EigenSolverReal` が返せない複素対を検出した場合は状態を返し、実数2値へ置き換えない。複素固有値を必要とする既存呼出しには `EigenSolverComplex` の返却型を維持し、複素の暗黙的単一シフトQRを実装する案を優先できる。

対称三重対角用のWilkinsonシフト式を、一般非対称行列へそのまま適用しない。二重シフト、2×2固有値抽出、複素回転にもスケーリングと全除算保護を適用する。構成の参考は [LAPACK DLAHQR](https://www.netlib.org/lapack/explore-html/d8/df4/group__lahqr_ga100049ab080cef756846702a33e8e28f.html) と [ZLAHQR](https://www.netlib.org/lapack/explore-html/d8/df4/group__lahqr_ga4fe407352fc5b1e1df796646498dd972.html)。固定予算と状態通知は本リポジトリ向けに設計する。

### EIG-3: 実対称行列向けの固定sweep Jacobi法を追加する【優先度: 中】

一般非対称用の置換ではなく、対称性が利用側で保証される場合の選択肢とする。`p < q` の全添字対を一定の順番で巡回し、J sweepを必ず実行する。

- 2×2対称部分の非対角を消す回転を、三角関数を使わず、差・積・平方根から計算する。
- `a(p,q) == 0` は恒等回転とする。対角が等しい場合も個別処理し、`(a(q,q)-a(p,p)) / (2*a(p,q))` を無保護で評価しない。回転生成はスケールして行い、`abs(tan(theta)) <= 1` の小さい角度の枝を選ぶ。
- 固有値だけなら行列の対称三角領域を保持する。固有ベクトルも必要なら単位行列に同じ回転を蓄積する。
- 1 sweepは `O(n³)`、全体は `O(J n³)`。小型対称行列での実装の単純さ、直交ベクトルを同時に得られる点を評価する。一般QRより常に高速とはしない。

重複固有値でも対称行列では直交基底を作る意味がある。一方、一般非対称行列の固有ベクトルに同じ直交化を強制してはいけない。三重対角化＋暗黙的QRは大きめの対称行列で有力だが、まずJacobiとの比較対象とし、両方を一度に実装する必要はない。

Jacobiの巡回順と回転式は、Golub–Van Loan『Matrix Computations』第4版の著者側公開コード [JacobiCyclic.m](https://www.cs.cornell.edu/cv/GVL4/M-Files/Chapter%208/Functions/JacobiCyclic.m) と [symSchur2.m](https://www.cs.cornell.edu/cv/GVL4/M-Files/Chapter%208/Functions/symSchur2.m) を参考にする。参照コードのwhileや動的配列を移植せず、本案は固定for・固定配列へ設計し直す。

### EIG-4: 既存GMRES逆反復の精度判定と予算を改善する【優先度: 中】

一般行列の固有ベクトルは、まず現行のGMRESを使う逆反復を維持する。逆行列ファイルへの別解法導入は行わない。

- 固有値用のsweep数、逆反復数、内側GMRESのK/C/Pを分離する。実数版で共用している `iteration_max` は互換設定を残しつつ、独立して選べるようにする。
- 現在の要素の絶対値差による収束判定に加え、`A v - lambda v` の実残差で評価する。符号・複素位相が変わっても同じ固有方向なので、成分差だけで成否を判定しない。
- `small_value` は行列スケールに応じたシフト摂動とする。小さすぎると内側の系が悪条件になり、大きすぎると目的の固有方向への収束が遅くなる。調整値と最終固有残差を併記する。
- 重複・近接固有値では同じベクトルへ収束することがある。対称行列の経路では既存ベクトルへの固定回数の直交化を検討する。一般非対称・欠陥行列にはn本の独立な固有ベクトルを無条件に要求しない。
- 正規化前の零判定と、内側GMRESの失敗状態を伝播する。未収束の固有値を使った固有ベクトルを成功扱いにしない。

## 6. LU分解の改善案

### LU-1: 各列の部分ピボット選択と正しい置換管理【優先度: 高】

現行は対角の絶対値が `division_min` 未満のときだけピボットを探す。対角が非零でも、その下に非常に大きい候補があれば乗数が大きくなるため、毎列 `argmax |A(i,k)|` を固定範囲で探索する部分ピボット選択を標準候補とする。同値のときは最初の行を選び、選択順序を確定する。

- `P A = L U` を再構成条件とし、右辺にも同じ置換を適用する。置換添字のgetterを追加し、PythonNumpy側にもこの規約を伝える。参照文献が `A = P L U` と定義する場合とはPの向きが逆になる。
- 現在の分離保存を維持する段階ではLの既確定列 `[0,k)` だけを交換し、単位対角を保持する。
- 行交換回数の偶奇を保持し、行列式へ符号を反映する。
- 全候補が微小なら特異・数値的階数落ちとして通知する。小さい対角を保護値へ置き換えたまま、元行列の正しい分解と扱わない。

探索は合計 `O(n²)`、分解は従来どおり `O(n³)`。探索コストは増えるが、数値安定性の改善を優先する。部分ピボットでもすべての行列について誤差が小さくなる保証はない。

入力の行ごとの尺度が大きく異なる用途では、行の最大絶対値等で割った比較値を使うスケール付きピボット選択も候補になる。この案ではAや右辺自体を正規化せず、行交換時に比較用スケールも交換する。スケール配列は `O(n)`、零行の検出とスケール除算の保護が必要である。ピボット探索を省くモードは、利用側が適切な行列クラスを保証し、別途評価した場合に限定する。

部分ピボットと因子の保存は [LAPACK DGETF2](https://netlib.org/lapack/explore-html/db/d4e/group__getf2_ga5f8f2998bad179dcee6a58d00599dba8.html) を参考にする。

### LU-2: LとUを単一配列へ保存し、逆数を共有する【優先度: 高】

下三角にLの乗数、対角以上にUを格納し、Lの対角1は暗黙とする。保持量を `2n²` から `n²` 要素へ減らす。置換添字n個は引き続き必要である。compact保存では行交換時に、既確定のL部分と更新中のU部分をともに正しく交換する。

各列の有効ピボットに対して `inv_pivot = 1 / safe(pivot)` を一度だけ計算し、各乗数を乗算で得る。分解中の同一ピボットに対する除算は約 `n(n-1)/2` 回から高々n回へ減らせる。後退代入を多数回行う用途では逆対角n個をキャッシュする案もあるが、RAMとの選択にする。極小ピボットの逆数がoverflowする場合は、単に逆数化を強行しない。

`get_L()` / `get_U()` は要求時に展開する。両方を毎回密行列として保持し直せばRAMの利点は失われる。既存クラスのメンバ構成を変更する際にはコピー・ムーブ操作とgetterもまとめて整合させる。

現行 `solve(A,b)` は呼出しごとに分解する。既存の `solve(A)` による分解と組み合わせて、分解済み因子から右辺だけを解く関数を追加する。同じAの複数右辺は、最初の分解 `O(n³)` と各右辺の代入 `O(n²)` にできる。行列Aを変えた後に古い因子を再利用しないよう、APIで因子の有効期間を明確にする。

### LU-3: 固定回数の反復改善を追加する【優先度: 中】

同じLU因子を使い、R回だけ `r = b - A x`、`L U delta = P r`、`x := x + delta` を繰り返す。R=0を最小時間、R=1または2等を精度重視の候補として比較する。追加計算は1回 `O(n²)`、追加領域は残差・補正の `O(n)`。

残差計算には元のAが必要である。入力を破壊してcompact LUへ変えた後にAを別途保存するなら、その `n²` 分をRAMへ算入する。元入力をconst参照で使える構成が望ましい。

float因子に対して残差のみdoubleで累積する選択肢もあるが、doubleがソフトウェア演算のマイコンでは時間増加が大きい。条件数・因子化誤差によっては改善しないため、追加回数による精度向上を保証しない。特異・失敗状態の因子を使って補正を続けない。

## 7. Cholesky分解の改善案

### CHOL-1: 上三角ワークでのin-place更新【優先度: 高】

現在の返却規約 `A = Yᵀ Y` を維持する。疎版は `U_dense` と `Y` の2個の密行列を局所保持するため、まずこの重複を除く。

1. 出力ワークYを毎回ゼロ初期化し、上三角に入力を配置する。疎入力では、現行が参照する下三角からCSRを一度走査して上三角へ散布し、入力の密コピーを作らない。
2. pivot kで `d = Y(k,k)` を正定値性・閾値の条件で確認する。
3. 対角 `r = sqrt(d)` と保護した `inv_r = 1 / r` を求め、`Y(k,k) = r` を保存し、行kの右側を `inv_r` で正規化する。
4. 後続上三角 `k < i <= j < n` に `Y(i,j) := Y(i,j) - Y(k,i) Y(k,j)` を適用する。

これはright-looking Choleskyであり、密行列の演算量は引き続き概ね `n³/3` FLOP。疎入力の局所ワークは `2n²` から `n² + O(1)` 要素へ減らせる。CSRから任意要素を何度も線形検索する実装を避けられる。

列優先の保存順序に合わせ、後続上三角更新では列jの内側で行iを進める。丸め誤差の伝播は現行の内積型と異なるため、特に正定値境界付近で比較する。現行方式より常に高速・高精度とはしない。基礎となるCholeskyの条件と因子の向きは [LAPACK DPOTF2](https://netlib.org/lapack/explore-html/de/db9/group__potf2_gac3e7c9b72833e5467d91259ce0d0d4d4.html) を参照する。

さらに上三角を `n(n+1)/2` 要素の固定配列へpacked保存できる。ただし既存返却型の密行列、fallback行列、PythonNumpyラッパの密・疎の二重保持は別途必要となる。packedコアを直接使う省RAM経路と、既存形式へ展開する互換経路を区別して見積もる。

### CHOL-2: 平方根・失敗時の扱いを統一する【優先度: 高】

- 対称正定値を前提とする。対称性を検査するなら固定の三角走査を追加する。利用側の保証で検査を省く場合も前提をAPIに記載する。
- sqrtの前にpivotの正値性と相対的な小ささを判定する。負値をクランプして分解成功にしない。
- 現行の `rsqrt(d)` を使って `1 / temp_inv` で対角を作る経路を残すなら、その除算にも保護を加える。`sqrt(d)` とその逆数を使う経路と比較する。
- `d * rsqrt(d)` に変えれば除算を減らせるが、近似誤差により対角と非対角で使う逆数の整合性が変わる。単純な高速化として一律採用せず、再構成誤差を評価する。
- 最後の対角だけ既定閾値の `sqrt(temp)` を使う現状を改め、全pivotで同じ精度・値域方針を使う。
- 失敗時は既存の `(Y_b, true)` 規約を保つ。反復枠を固定する構成では失敗フラグを保持し、以後の数値更新を行わず最後にfallbackを返す。
- 対角版の零許容を残すなら、零に対する出力は正確に0とする。対角版の半正定値許容と、一般版の正定値要求を文書化する。

### CHOL-3: 平方根を避けたいSPD用途にはLDLᵀを追加する【優先度: 中】

`A = L D Lᵀ`、Lの対角を1とし、Dと下三角の乗数を保持する。SPD入力なら正のDを確認しながら、平方根なしで分解できる。各Dの逆数を保護して1回だけ計算し、後続更新で共有する。

密行列の計算量の次数は `O(n³)` のままで、削減対象は平方根のn回と出力形式による記憶量である。平方根のコストが大きいマイコン、L/Dを直接使える処理で評価する。

既存 `cholesky_decomposition` の出力をLやDへ黙って変更しない。別関数または別クラスとして追加する。従来の上三角因子が必要なら `Y = sqrt(D) Lᵀ` へ変換するため、平方根削減の利点は小さくなる。一般の対称不定値行列への適用は提案しない。それには別途1×1/2×2ピボットを含む設計が必要である。

## 8. GMRESの範囲内での改善案

### GMRES-1: 作業領域を圧縮する【優先度: 高】

実数dense版 `gmres_k_core` は `r: n×n`、`q: n×(n+1)`、`h: (n+1)×n` を保持する。これだけで `3n² + 2n` 要素であり、別に `O(n)` のベクトルを使う。疎入力でもKrylov基底は一般に密である。

Arnoldiで得たHessenberg列は、生成後にそれまでのGivens回転と新しい回転を適用すれば、Rの1列になる。将来必要なのは回転後の上三角Rなので、**h全体とr全体を別々に保持する必要はない**。

- 現在のHessenberg列だけを長さ `K+1` のワークに作る。
- 変換後のRを `K(K+1)/2` 要素のpacked上三角へ保存する。
- 基底は `n×K` とし、次の基底候補は既存の長さnのvで保持する。最終反復でも末尾の `h(K,K-1) = norm(v)` とGivens回転は計算し、次の基底の正規化・保存だけを省く。現行の最終段の条件分岐をそのままKへ移すと、K<nで推定残差を誤って0にするため注意する。
- Givens係数、右辺、係数y、残差等は `O(n+K)`。作業領域は `nK + K(K+1)/2 + O(n+K)` 要素になる。

例えばn=16、K=16、floatなら、大きい行列領域だけで現状 `800×4 = 3200 byte`、提案 `392×4 = 1568 byte`。差は1632 byte。これは追加ベクトル・入力・返却行列・アラインメント・一時コピーを除いた比較である。複素版では実際の `sizeof(Complex<T>)` で計算する。

逆行列の各列は同じワーク領域を順次再利用する。単位行列B全体を作らず、その列の単位ベクトルだけを生成する。`gmres_k_matrix_inv` 等の入力A・初期値Xの値渡しもconst参照の内部経路にできる。ただし異なる右辺のKrylov基底を無条件に流用してはいけない。

### GMRES-2: Kとcycle数を事前設定する【優先度: 中】

現行の平方行列用コアは通常最大n回の1 cycleで、任意のKや再始動cycle数を独立には指定しない。これを、`1 <= K <= n` の固定容量を持つGMRES(K)と、固定cycle数Cへ拡張する。K=n、C=1を現行に近い予算として残す。

- 各cycleで真の残差 `b-Ax` を計算し、GMRESをK枠実行してxを更新する。
- cycle間で基底とRを再初期化する。内部残差・breakdown状態も持ち越し方を規定する。
- 実数denseなら概ね `O(C(K n² + n K²))`、CSRなら `O(C(K nnz + n K²))`。残差再計算等も予算に含める。
- Kを小さくするとRAMと直交化コストが減るが、再始動により収束が遅くなる・停滞する場合がある。Cを増やしても任意の系で精度を保証できない。

この変更はGMRESの再始動・作業領域制御であり、別の反復解法への置換ではない。再始動の性質は [Netlib GMRES](https://netlib.org/linalg/html_templates/node29.html) と [実装上の説明](https://netlib.org/linalg/html_templates/node31.html) を参照する。

### GMRES-3: 直交化・breakdown・残差判定を改善する【優先度: 高】

現行のArnoldi直交化は、各内積後にvを更新するMGSである。これを新規MGSへの置換と説明しない。

- 精度重視ではMGSを固定2 passとし、2回目の内積補正を同じHessenberg列へ加算する。P=1/2を事前選択する。直交化時間は増えるが基底の直交性改善が期待できる。
- 初期残差が零なら解を保存し、後続枠を無効化する。sqrtで零が正値に変わる前に判定する。
- Arnoldi後のvが零・微小なら、次基底を正規化しない。現在の小さい最小二乗問題までで解を更新し、真の残差からhappy breakdownか解けないbreakdownかを判定する。
- 小さいRの対角が特異なら、保護値で巨大なyを作って成功扱いにせず、状態を返す。失敗後は既知の有効なxを保持する。
- 実数版のrhoはノルム、複素版のrhoは二乗ノルムとなっている点を整理する。新しい共通コアでは実残差ノルムまたは二乗ノルムに統一し、既存APIの返却値を変える場合は互換性を明示する。
- `rho` と `decay_rate` の比較は単位を揃える。例えばノルムで `rho <= abs_tol + rel_tol × norm_b` とする。二乗形なら閾値も二乗し、overflow/underflowを避ける。初期残差に対する比を維持するAPIと、bに対する比の新APIを混同しない。
- 少なくとも最後のxに対して `b-Ax` を直接計算して確認する。Givensから得る推定残差だけで成否を決めない。

正規化の逆数はベクトルごとに1回計算して共有できる。小さいサイズでは効果が限定的なので、ワーク削減と正確性の修正を先に行う。

### GMRES-4: スケーリング付きの実数・複素Givensを共通化する【優先度: 高】

実数版は `f*f + g*g` を直接計算せず、2要素の最大絶対値でスケーリングする。f=g=0は恒等回転として処理する。

複素版は、次の形を満たす**実数c、複素数s**を用いる。

```text
[ c          s ] [ f ] = [ r ]
[ -conj(s)   c ] [ g ]   [ 0 ]
c*c + abs(s)^2 = 1
```

fとgが非零の場合の数学的な式は、`alpha = f / abs(f)`、`d = sqrt(abs(f)^2 + abs(g)^2)`、`c = abs(f)/d`、`s = alpha*conj(g)/d`、`r = alpha*d`。実装ではそのまま二乗和・除算を評価せず、スケーリングと分母保護を行う。g=0はc=1、s=0、f=0はc=0としgの位相を使う別処理とする。

現行式では、例えばf=i、g=1で生成される回転がユニタリにならない。この修正はGMRESそのものを維持した数値カーネルの修正である。位相と特殊ケースは [LAPACK ZLARTG](https://www.netlib.org/lapack/explore-html/da/dd3/group__lartg_ga1e266e78a9a8585a1fc67f2d23badc64.html) を参照する。

### GMRES-5: 用途を限定した追加候補【優先度: 低〜中】

**対角前処理:** 固定の右前処理 `A D⁻¹ z = b` を候補とする。DはAの対角等から事前構成して全cycleで固定し、逆対角n個を保存する。小さい対角は1へ置換してその成分の前処理を無効にする等、有限かつ非零のDを選び、逆数の分母も保護する。各cycleでは残差r₀に対する `A(D⁻¹ delta_z) = r₀` を解き、Arnoldiの積を `A(D⁻¹ q_j)` とする。追加RAMは `O(n)`、適用コストは反復当たり `O(n)`。尺度のばらつきに効果がある場合があるが、一般に改善する保証はない。K次元の係数yを使って `x += D⁻¹ Q y` と更新し、判定は元の系の実残差で行う。

**縦長行列版:** 現行 `gmres_k_rect` / `sparse_gmres_k_rect` は `AᵀA` を明示的に作る。GMRESをそのまま使い、演算子を `v -> Aᵀ(Av)` とすれば、Gram行列 `n²` の保存と構築を省ける。代わりに長さmの作業ベクトルと各反復で2回の積が必要であり、denseでは構築・積の `O(m n² + K n²)` と `O(K m n)` を比較する。これに両方式共通の直交化 `O(n K²)` が加わる。右辺数・cycle数も含めて比較し、sparseではGramのfill-in回避も評価する。**正規方程式の条件数が概ね二乗になる問題は解消しない**。別の最小二乗法への変更は今回提案しない。

矩形版のGMRESの右辺は `Aᵀb`、初期残差は `Aᵀ(b-Ax)` である。不整合な最小二乗問題では `b-Ax` は零にならないため、適切にスケールした `Aᵀ(b-Ax)` の小ささを停留条件として評価し、元残差の大きさも目的値として報告する。8節の平方系向け実残差判定を、矩形版へそのまま適用しない。

## 9. 実装優先順位と設定の選び方

| 段階 | 内容 | 完了条件 |
|---|---|---|
| 1 | 依存経路の禁止事項整備、全除算保護、3節の不整合修正、固定反復・状態の定義 | C++11・固定配列構成でビルドし、再現例と異常入力を安全に処理 |
| 2 | EIG-1/2、LU-2、CHOL-1、GMRES-1、QR参照更新 | 同等の数値条件で、最大スタック・保持量・演算時間を測定 |
| 3 | Householder QR、対称Jacobi、LDLᵀ、再始動GMRES | 適用条件を持つ別経路として既存APIと比較 |
| 4 | 固定回数の反復改善、MGS pass数、sqrt精度、前処理の選定 | 対象行列群で時間・RAM・誤差の比較表を作成 |

設定例はあくまで評価候補とし、既定値を未測定で決めない。

| 調整軸 | 小さくする・省略する場合 | 大きくする・有効にする場合 |
|---|---|---|
| 固有値S / Jacobi J / 逆反復V | 時間が短い、未収束が増える可能性 | 時間が増える、改善の程度は入力依存 |
| GMRES K | RAM・直交化時間が減る、再始動停滞に注意 | RAMが増える、1 cycleの探索空間が広がる |
| GMRES C | 時間予算が小さい | より多く補正できるが収束保証ではない |
| MGS P=1/2 | 最小の直交化時間 | 追加passで丸め誤差による直交性喪失を抑える |
| LU補正R=0/1/2等 | 分解・代入のみ | 元行列の残差計算と代入が追加される |
| sqrt / rsqrtの精度 | 低コスト、直交性・分解精度が悪化し得る | 高コスト、行列の悪条件性までは解決しない |
| Q・固有ベクトルの生成 | 値・因子だけなら時間とRAMを削減 | 出力行列分の時間とRAMが必要 |

`division_min` を大きくすることを、一般的な高速化や精度調整の主軸にはしない。これは主に数値保護の設定であり、変更すると階数・特異性・元の問題の扱いまで変わり得る。

## 10. 実装時の検証計画

### 10.1 数値的な受入れ条件

| 対象 | 評価するもの |
|---|---|
| QR | 相対再構成誤差、`QᵀQ-I`、Rの下三角、同一インスタンスの繰返しsolve |
| 固有値・固有ベクトル | `A v-lambda v`、未収束ブロック、実数/複素対、継続計算。直交性は対称/Hermitianに適用 |
| LU | `P A-L U`、L単位対角、置換の整合、行列式の符号、`b-Ax` |
| Cholesky / LDLᵀ | `A-YᵀY` / `A-LDLᵀ`、pivotの正値性、失敗flagとfallback |
| GMRES（平方系） | 元の系の `b-Ax`、逆行列なら `I-A X`、内部rhoとの一致、breakdown状態 |
| GMRES（矩形系） | 正規方程式の `Aᵀ(b-Ax)`、目的値としての `norm(b-Ax)`、内部rhoの定義との一致 |

相対誤差は、例えば `norm(error) / safe(norm(reference), positive_floor)` で評価する。比較用指標でも零除算を避ける。零入力については絶対誤差も併記する。float/doubleで同じ絶対許容値を一律に使わず、サイズ・入力スケール・条件の違いを考慮する。参照値の生成はホスト上の既存Pythonサンプル等を利用できるが、禁止ライブラリをターゲットコードへ持ち込まない。

入力には、1×1、零・単位・対角、矩形、非零のfill-inが生じる疎行列、零ピボットだが正則な行列、階数落ち、悪条件、大小の尺度混在、非対称、近接・重複固有値、複素共役対、SPD・半正定値・不定値を含める。GMRESでは初期残差零、happy breakdown、特異系、純虚部を含む回転を必須とする。設定値0・負の閾値・0反復の扱いも固定する。

ピボット選択を強化すると、正しいL/Uでも現行テストの要素ごとの期待値と異なる場合がある。QRの符号や固有ベクトルの位相も一意ではない。因子・ベクトルの特定表現だけで合否を決めず、置換を含む再構成と残差を中心に検証する。

### 10.2 構成・RAM・時間

- 既存CIに合わせ `-std=c++11 -Wall -Wextra -Werror` を基本とする。既存 `test_vs/test_vs_main.cpp` のfloat/double・Base/PythonNumpy両層と、新しい数値条件の試験を実行する。
- 組み込み設定での `<cmath>` 不使用、`while`・例外・動的確保の禁止を、対象APIから到達する依存コードまで確認する。`<algorithm>` は使用可能である。`-fno-exceptions` だけでは全条件の証明にならない。
- ヒープ監視はソルバだけの小さな実行体で、構築・solve・getterを含めて行う。ホスト用テスタ自身の動的確保と区別する。
- `sizeof` に加え、コンパイラのスタック使用量出力・リンク情報・実機計測で最大RAMを確認する。C++11の戻り値最適化を前提にせず、tuple返却・getter・ラッパの一時行列も数える。
- 同じ行列、同じ許容誤差、同じ最適化・FPU設定で比較する。平均時間だけでなく、設定した全反復予算を消化する場合の最悪時間を測定する。
- 速度とRAMが改善しても数値条件を満たさなければ採用しない。逆に安定性向上のため時間が増える設定は、その増加量を示して選択可能にする。

初回調査ではソース・依存関数の確認と3節の小型再現を行った。今回の追補では `<algorithm>` を許可する前提へ更新し、`base_math_arithmetic.hpp` の `<cmath>` インクルード条件を修正した。提案アルゴリズムの実装、その適用後の全体回帰試験、マイコン上の性能測定は未実施であり、実装段階で上記の受入れ条件を満たす必要がある。
