# GMRESの改善前後と反復回数の上限

確認日: 2026-11-12

## 1. 既存APIの反復上限は増えていない

**正方行列 `A` の行数を `N` とすると、既存の `gmres_k` などは現在も、右辺1本の求解につき最大 `N` 回のGMRES更新を行う。新しい `GmresSolver<T,N>` の既定設定も同じである。** 未収束だからといって、この上限を自動的に増やす処理はない。

改善時に追加した再始動GMRESでは、利用側が複数サイクルを明示すると、1回の `solve` で合計 `N` 回を超える設定を選べる。これは任意の設定であり、既存APIの既定動作ではない。

前回説明した「平均15.5回から24回」「計算時間が約52%増加」は、**測定側で `K=8`、`cycles=4` を指定した、最大32回の再始動構成**の結果だった。元の「最大16回」の構成との比較ではない。既定動作と任意設定の区別が説明不足だったため、本書で訂正する。

## 2. 「改善前」の時点を分ける

| 時点 | リビジョン | GMRESの実装 |
|---|---|---|
| 元のアルゴリズム | `b7faabf` | `base_matrix_inverse.hpp` 内で実装。1回の求解は最大行数回。`decay_rate` で途中終了 |
| アルゴリズム改善後、平方根方針変更前 | `f50060e` | 共通コア、状態通知、実残差の確認を追加。既存APIは1サイクルを維持し、新クラスで任意の再始動を追加 |
| 現在 | `879a319` | 平方根を数学ライブラリの公開APIに委譲。近似ノルムに対応する直交化へ修正。既定サイクル数は引き続き1 |

約52%の時間差を測定したのは、表の2行目と3行目である。**比較の両側に同じ `K=8`、`cycles=4` を指定しており、直近の平方根変更で反復上限を増やしたわけではない。**

## 3. 反復回数の数え方

本書の「1回のGMRES更新」は、行列ベクトル積から新しい探索方向を作り、直交化と回転を行う1段の処理を指す。コードではArnoldi更新に相当し、`rep_num` / `get_iterations()` が数える単位である。

| 記号・設定 | 意味 | 既定値 |
|---|---|---|
| `N` | 正方行列の次元、未知数の数 | 行列の型で決まる |
| `K` | 保持できる探索方向の数。1サイクルの更新上限 | `N` |
| `C = cycles` | 初回を含むサイクル数の上限。2回目以降は前の解と残差を引き継ぎ、探索方向を作り直す | `1` |
| `P = orthogonalization_passes` | 各更新の中で直交化を繰り返す回数 | `1`、任意で2 |

`krylov_dimension` を既定値のまま使う場合、上限は次のようになる。

```text
1回のsolveにおけるGMRES更新数 <= K × C

既定: N=16, K=16, C=1
    [最大16更新] → 終了                    合計最大16更新

任意: N=16, K=8, C=4
    [最大8更新] → [最大8更新] → [最大8更新] → [最大8更新]
                                               合計最大32更新
```

`C=4` は初回1サイクルと最大3回の再始動を表す。各サイクルの後続処理は、収束・breakdownなどの状態に応じて省略するため、必ず4サイクルを実行するという意味ではない。

`krylov_dimension` やpartitionの有効次元を小さく指定した場合は、その分だけ上限も小さくなる。正確には、範囲補正後の実効次元を `d` として `更新数 <= C × d <= C × K`。`cycles=0` なら更新数は0である。

**`P=2` は直交化の演算量を増やす設定であり、GMRES更新数を2倍にする設定ではない。** `get_iterations()` は各 `solve` の開始時に0に戻り、その呼出し内の全サイクルの実更新数を合計する。

また、上限のある `for` と状態フラグを使うことと、常に上限回数の数値計算を行うことは異なる。現在は停止後の数値更新をフラグで無効化するため、実更新数も実行時間も入力によって変わる。

## 4. `decay_rate` の役割と変更点

### 元の実数GMRES

元の一般の実数版は、概ね次の条件だった。

```text
r0 = b - A*x0
最大N回の更新中に:
    推定残差 / 保護した初期残差ノルム < decay_rate
なら途中終了
```

実コードの `b_norm` は、名前に反して右辺 `b` のノルムではなく、初期残差 `b-A*x0` のノルムである。停止判定は厳密な `<` 比較なので、有限値の通常の経路では `decay_rate=0` にするとこの条件では止まらず、最大 `N` 回まで計算していた。したがって、元の設計に対する「既定では行数回が最大」という理解は正しい。

### 現在の実数・複素数共通コア

既存APIの `decay_rate` は、新クラスの `relative_tolerance` に渡している。現在の閾値は次のとおり。

```text
停止閾値 = max(absolute_tolerance, 0)
           + max(relative_tolerance, 0) * norm(b)

既存APIでは absolute_tolerance = 0
            relative_tolerance = decay_rate（負値は0として扱う）
```

内側の更新は推定残差がこの閾値以下になると停止し、候補解を作った後に `norm(b-A*x)` を再計算して最終的な収束を確認する。推定残差だけが小さくても、再計算した残差が条件を満たさなければ、収束したとは通知しない。残りのサイクル枠があり、breakdownしていなければ再始動できるが、既定の `C=1` ではそのまま結果を返す。

`decay_rate=0` でも、現在は次の場合に上限より少ない更新数となる。

- 初期解が既に解になっており、計算した初期残差が0である。
- 更新中の推定残差が0になる。
- 新しい独立な探索方向を作れなくなる、または小さい三角系を安全に解けなくなる。

最後の状態をbreakdownと呼ぶ。解が得られている場合もあるため、実残差を確認して収束と未収束を区別する。これらの追加判定は更新数を減らす方向に働き、既定上限 `N` を増やすものではない。

### 同じ `decay_rate` の意味は完全互換ではない

| 項目 | 元の実装 | 現在 |
|---|---|---|
| 実数の相対基準 | 初期残差 `norm(b-A*x0)` | 右辺 `norm(b)` |
| 実数の境界比較 | `<` | `<=` |
| 複素dense | 推定残差の二乗を初期残差ノルムの二乗で割って比較 | 残差ノルムを使用 |
| 複素sparse | 推定残差の二乗を初期残差ノルムで割って比較し、denseと不統一 | 実数・複素denseと同じ基準へ統一 |
| 返却する `rho` | 回転計算から得た残差の推定値。複素版は二乗値 | 返却解の `norm(b-A*x)` を再計算した値 |

例えば、初期残差ノルムが `0.1`、右辺ノルムが `100`、`decay_rate=0.01` なら、入力下限の影響を受けない実数の比較で、旧条件の閾値は `0.001`、現条件の閾値は `1` となる。初期解を前回の解から引き継ぐ場合などは、同じ設定値でも停止時点が変わり得る。

この変更は単なる実装整理ではなく、停止条件の意味の変更である。関数の引数は維持しているが、従来の初期残差基準や複素二乗残差を前提とした設定は見直す必要がある。`decay_rate=0` の場合も、前述の零残差・breakdown判定の違いは残る。

## 5. アルゴリズムの処理はどう変わったか

GMRESという解法自体は維持している。変更は、作業領域、数値保護、停止・状態判定、任意設定の追加である。

| 処理 | 元の実装 | 現在の実装 |
|---|---|---|
| 初期残差 | `b-A*x0` を計算して正規化 | 同じ処理に加え、零残差なら正規化前に終了。ノルム計算をスケーリング |
| 探索方向の生成 | 行列ベクトル積と1-passの修正Gram–Schmidt法 | 同じ基本手順。任意で2-pass。現在は基底の実際の二乗長で射影係数を補正 |
| 回転と残差の更新 | 実数・複素数などで別実装 | 共通コアに整理し、複素回転・最後の更新段の扱いを修正 |
| 作業領域 | Q・H・Rなどをそれぞれ行列として保持 | 必要な基底、Hの1列、Rの上三角だけを保持。Kを小さくする省RAM設定を追加 |
| 解の更新 | 三角系を解いて初期解へ補正を加える | 小さい三角系の不適合を通知。実残差が悪化する候補は採用せず保持中の解を返す |
| 最終確認 | `rho` は回転からの推定値 | `b-A*x` を計算し直して確認。状態取得用APIを追加 |
| 再始動・前処理 | 通常APIには設定なし | 新クラスで任意に指定。既存APIでは再始動・対角前処理を自動で有効化しない |
| 平方根 | 元版は外部の公開APIを使用。改善の途中で行列側の反復数指定を追加 | 現在は公開 `Base::Math::sqrt` / `rsqrt` に再統一し、行列側の精度設定を撤去 |

直近の直交化修正は次の変更である。`v` は保持中の基底、`w` は直交化するベクトル、`vᴴ` は複素共役転置を表す。

```text
変更前: 射影係数 = vᴴ*w
現在:   射影係数 = (vᴴ*w) / (vᴴ*v)
```

近似平方根で正規化すると、`vᴴ*v` が厳密な1にならない場合がある。その実際の長さを使って射影する修正であり、平方根の精度を行列側で調整する処理ではない。二乗和と除算は増えるが、探索方向を1本追加したことにはならない。

**GMRES更新数と、行列ベクトル積の総回数・計算時間は別である。** 一般の正方行列・1サイクルで `N` 回更新する例では、元版の行列ベクトル積は初期残差用1回と更新用N回。現在の通常経路では、これに候補解の実残差確認用1回が加わる。候補解を拒否した場合は保持中の解の残差計算も追加される。更新上限が同じ `N` でも、計算時間が同じになるとは限らない。

## 6. 前回の「24回」「約52%増加」の内訳

対象は通常行列のfloat 16×16、`K=8`、`C=4`、`P=1`、対角前処理あり、相対・絶対許容値0の設定だった。

| 項目 | 平方根方針変更前 `f50060e` | 現在 `879a319` |
|---|---:|---:|
| 指定した最大更新数 | 8×4＝32 | 8×4＝32 |
| 1000試行の平均更新数 | 15.5 | 24 |
| 更新数の範囲 | 7〜24 | 24 |
| 収束／breakdownの試行数 | 500／500 | 1000／0 |
| 1求解の時間（5プロセスの中央値） | 5.402 μs | 8.195 μs |

同じ上限の中で、以前は途中でbreakdownしていた試行も更新を続けたため、平均更新数が増えた。使用型で再計算した残差に基づく収束であり、厳密な実数演算での残差0を保証するものではない。

一方、同じ測定群のdouble 16×16・`K=16/C=1/P=1`・前処理なしでは、前後とも16更新で、時間は6.804 μsから6.970 μs（約2.4%増）だった。元の上限と比較する際には、このように再始動なしの構成を使う必要がある。

これらは同一CPU・C++11・`-O2` でのホスト測定。各版の平方根の既定精度も異なるため、同じ精度を保証した速度比較ではなく、MCUの実機時間・最悪時間を示すものでもない。

## 7. 行数以内の上限を維持する使い方

既存の `gmres_k(A, b, x0, decay_rate, division_min)` は、変更せずに利用できる。新クラスでも、次の既定構成なら1右辺につき最大16更新である。`A`、`b`、`x0` は16次元の行列・ベクトルとして用意しておく。

```cpp
Base::Matrix::GmresSolver<float, 16> solver;
solver.cycles = 1;                 // 既定値。再始動しない。
solver.relative_tolerance = 0.0F; // 既存APIのdecay_rate=0に対応。
solver.absolute_tolerance = 0.0F; // 既定値。
auto x = solver.solve(A, b, x0);
auto updates = solver.get_iterations(); // 0～16。
```

新クラスでRAM削減のため `K<N` を選び、再始動も使用する場合は、上限を `N` 以下にする十分条件として `K×cycles <= N` を設定できる。例として `N=16/K=8/C=2` は最大16更新。ただし、基底を作り直すため `K=16/C=1` と同じ計算過程・精度になるとは限らない。

上限を読む際の補足:

- 複数右辺や逆行列では、上限は右辺1本ごと。N×Nの逆行列はN本を解くので、全体の合計は最大N²更新となる。
- M×Nの縦長行列はN×Nの正規方程式を解くため、既定上限は元行列の列数N。
- 固有ベクトルの逆反復からGMRESを呼ぶ場合、外側の逆反復回数と、各GMRES呼出しの上限は別。
- 元の1×1専用処理は直接除算で `rep_num=0`。現在は共通コアを使うため0または1であり、この特殊ケースの返却カウントは変わっている。
