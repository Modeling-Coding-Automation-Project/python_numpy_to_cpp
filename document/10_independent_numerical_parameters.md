# 用途別の固定しきい値による運用の調査

セクション1〜8は調査対象 commit 時点の記録。2026-11-17に候補Aを本体へ反映した内容は、[セクション9](#9-固定パラメータの採用2026-11-17)を参照。

その後の[実行時間・RAMの追加調査](11_execution_time_and_peak_ram_recheck.md)では、一部の時間・スタック使用量の増加と、8次floatの固有ベクトル品質の悪化を確認した。本書の有限の試験集合で得た候補Aを、全入力で性能が悪化しない設定とは扱わない。

## 1. 結論

**収束許容誤差・GMRES の breakdown 判定・逆反復のシフト量を、別々の固定パラメータとして運用できる。これらを機械 epsilon に連動させる必要はない。**

さらに、収束許容誤差は「固有値」「固有ベクトル」「逆反復内部の GMRES」に分けると、調整の目的が明確になる。今回の試験では、breakdown 係数だけを小さくして探索を継続できた例、シフトだけを小さくして精度が悪化した例、内側の許容誤差を厳しくして収束判定が成立しなくなった例を確認した。

Base::Matrix の既存 API では、breakdown 係数以外はすでに別々に指定できる。breakdown 係数と各パラメータの既定値を名前付き定数にすることで、インスタンスの RAM を増やさずに固定値で調整できる。一時コピー上でこの構成を試作し、C++11 の既存回帰試験も通過した。

本調査では本体・外部ライブラリのヘッダを変更していない。追加したものは測定プログラム、結果、本文書である。設定候補は今回の入力集合で確認した値であり、全行列に対する最適値ではない。

## 2. 分けるパラメータと調査時点の API

以下の値は `epsilon` の代わりに入れてから 8 倍・32 倍する基準値ではなく、**各判定に直接使う最終的な相対係数**である。

| 記号 | 目的 | 現在の指定箇所 | 定数化する場合の名前の例 |
| --- | --- | --- | --- |
| β | GMRES で次の探索方向を残すか判定 | `8 * epsilon()` が内部に固定されている | `GMRES_BREAKDOWN_RELATIVE_TOLERANCE` |
| rtol | 固有値計算の非対角成分を無視する基準 | `relative_tolerance` | `DEFAULT_RELATIVE_TOLERANCE_EIGEN_SOLVER` |
| vtol | 逆反復で求めた固有ベクトルの残差への要求 | `eigenvector_tolerance` | `DEFAULT_EIGENVECTOR_RELATIVE_TOLERANCE` |
| μ | 逆反復で固有値からずらす相対シフト量 | `small_value` / `set_small_value()` | `DEFAULT_EIGENVECTOR_RELATIVE_SHIFT` |
| η | 逆反復内部の線形求解への要求 | 正の `gmres_k_decay_rate` | `DEFAULT_INNER_GMRES_RELATIVE_TOLERANCE` |

単独で使う GMRES の収束許容誤差 τ は、既存の `relative_tolerance` で指定する。β と τ は別の判定であり、役割は次のように異なる。

- GMRES の収束判定：`残差 <= absolute_tolerance + τ * ||b||`。
- Arnoldi の breakdown 判定：`直交化後の長さ <= β * 直交化前の長さ`。
- 一般固有値の分離判定：`非対角成分の大きさ <= absolute_tolerance + rtol * 局所スケール`。
- 逆反復のシフト：`perturbation = max(abs(μ) * 入力スケール, division_min)`。

`division_min` はゼロ除算回避用であり、上記の相対係数と統合しない。絶対許容誤差も引き続き別に設定できる。

現状の API を使う際には、次の点に注意する。

- コンストラクタは `small_value` に `sqrt(epsilon)` の下限を適用するが、構築後の代入・`set_small_value()` はその下限を再適用しない。今回の試験では構築後に μ を指定した。固定既定値へ移行する試作では、このコンストラクタ内の下限処理も外した。
- `gmres_k_decay_rate > 0` なら指定値がそのまま使われる。現在は 0 以下を指定すると `16 * sqrt(epsilon)` に戻る。固定値運用では正の η を指定するか、この未指定時の値も独立した固定定数にする。
- μ を小さくしても `division_min` による保護は残る。正の μ を設定しても、浮動小数点でシフトが丸め落ちる場合や別の固有値と一致する場合があり、シフト後の行列が必ず正則になるという保証ではない。
- 固定定数を `static_cast<T>(...)` して使っても、格納値には通常の型ごとの丸めがある。指定値が型非依存でも、結果まで型非依存になるわけではない。

上記は Base::Matrix 側の API の説明である。`python_numpy` 側のラッパーでは内部ソルバが保護され、rtol・vtol の公開 setter がない。`set_small_value()` は実数・複素数、dense・sparse で利用できるが、`set_gmres_k_decay_rate()` の公開範囲も一様ではない。ラッパーからインスタンスごとに調整したい場合は、内部メンバーへ渡す setter の追加が必要になる。名前付き既定定数だけで運用する場合は、ラッパーにもその既定値が反映される。

## 3. 試験条件

対象は commit `8e22c7b327fa4d783a0db33527cc25b5d941b8ba` と、その commit のサブモジュール。作業ツリーを変更せず一時領域に展開した。g++ 15.2.0、C++11、`-O2 -Wall -Wextra -Werror`、固定配列を使用した。

| 試験 | 変更したパラメータ | 件数 |
| --- | --- | ---: |
| 単独 GMRES | β 3値 × τ 4値、直交化1回・2回、実数・複素数、通常行列・near-breakdown | 672 |
| 固有値・固有ベクトル | β・rtol・vtol・μ・η の132組 × 数学設定2種 × 型2種 × 22ケース | 11,616 |
| 固定値を既定値にする試作 | GMRES・Eigen・制約監視の既存試験 × template / for | 6実行 |

既定の数学ライブラリ構成と、原因を分離するためのホスト専用 `BASE_MATH_USE_STD_MATH_` 構成を比較した。後者を組み込み用に採用する提案ではない。両者とも `float` と `double` を試した。

固有値の基本グリッドは β=`{8e-7,8e-12,8e-16}`、rtol=`{8e-7,8e-12}`、vtol=`{3.2e-6,3.2e-12}`、μ=`{1e-3,1e-6,1e-9}`、η=`{5e-3,1e-6,1e-12}` の108組。基本グリッドのシフト間隔が粗かったため、前回の共通 `1e-7` 設定の近傍などを含む24組を追加した。これは探索的な比較であり、候補選定に使用した入力を独立の未知データとは扱わない。

固有値の22ケースは 3×3 の一般実数7件、一般複素数9件、対称 Jacobi 6件。通常、非正規、近接・重複固有値、複素共役、巡回、`1e-12` / `1e12` のスケールを含む。反復上限は一般 QR 128、逆反復30、Jacobi 10、内部 GMRES は `K=N=3, cycles=1` に固定した。

GMRES は実数6×6・複素数4×4の通常集合と、2×2の near-breakdown 集合を用いた。`K=N, cycles=1`、絶対許容誤差0とし、`division_min` は GMRES 単独で `1e-25`、固有値側で `1e-20` に固定した。

品質は指定した許容誤差とは独立に評価した。GMRES は格納済み入力に対する Decimal 80桁の参照解を120桁でも照合し、前進誤差と実残差を計算した。固有値は格納済み入力を NumPy binary64 で参照計算し、以下を測定した。

- 固有値誤差：対応を合わせた最大固有値差を `||A||F` で割った値。
- 固有対残差：`max ||Av - λv||2 / (||A||F * ||v||2)`。

固有値側の品質ゲートは両指標とも `2e-6` 以下とし、ホスト std double の高精度試験だけ `1e-10` 以下とした。収束フラグは別に集計した。これらは比較用の評価基準であり、あらゆる用途で十分な精度を定義するものではない。

## 4. GMRES：breakdown と収束許容誤差を分ける効果

次の行列は、非常に小さい残差でも解の誤差が大きくなり得る例である。

```text
A = [[1, 0], [2e-10, 2e-10]]
b = [1, 0]
真の解 = [1, -1]
```

既定数学・double・直交化1回の結果：

| β | τ | 反復数 | 収束 | breakdown | 相対前進誤差 | 相対実残差 |
| --- | --- | ---: | --- | --- | ---: | ---: |
| `8e-7` | `1e-12` | 1 | false | true | `0.7071` | `2e-10` |
| `8e-12` | `1e-12` | 2 | true | false | `0` | `0` |
| `8e-12` | `1e-6` | 1 | true | false | `0.7071` | `2e-10` |

1行目から2行目では、βだけを小さくすることで必要な探索方向を残し、正解まで進んだ。2行目から3行目では、τだけを緩めたため、残差が要求を満たした段階で終了した。**βを小さくしても、τが緩ければ精度の高い解まで進むとは限らない。** これは各設定の意図に沿った動作である。

通常集合では β=`8e-16`, τ=`1e-6` で両型とも8/8件が収束し、相対前進誤差は `1e-6` 未満だった。ただし double に `1e-12` の前進精度を要求すると6/8件にとどまる。一方 float で τ=`1e-12` にすると、前進誤差が約 `5.9e-7` 以下でも通常集合の収束判定は0/8件だった。解の品質と、指定条件に対する収束状態は区別する必要がある。

## 5. 固有値・逆反復：固定値を組み合わせた結果

既定数学・両型に共通して使用できた候補 A は次の組合せだった。

```text
β    = 8e-12     GMRES breakdown
rtol = 8e-9      固有値
vtol = 3.2e-6    固有ベクトル
μ    = 3e-4      逆反復シフト
η    = 5e-3      逆反復内部の GMRES
```

以下の「品質と収束」は、固定品質ゲートと固有値の収束、一般固有値では固有ベクトルの収束も満たした件数。基準と共通 `1e-7` は[前回調査](09_epsilon_parameter_sweep.md)の同一入力・同一 commit のデータを同じゲートで再集計した。

| 数学設定・型 | パラメータ | 品質と収束 / 22 | 最大固有値誤差 | 最大固有対残差 | QR sweep 合計 |
| --- | --- | ---: | ---: | ---: | ---: |
| 既定 float | 現状の machine epsilon | 22 | `6.67214e-7` | `1.26135e-6` | 42 |
| 既定 float | 共通 `1e-7` | 22 | `6.67214e-7` | `1.16229e-6` | 42 |

| 既定 double | 共通 `1e-7` | 22 | `5.70338e-7` | `1.13367e-6` | 42 |
| 既定 double | 独立設定 A | 22 | `3.00998e-7` | `7.77353e-7` | 45 |

候補 A は両型で固有値22/22件、一般固有ベクトル16/16件の収束が成立し、内部 GMRES 失敗フラグも0件だった。現状の既定 double も品質ゲート自体は22/22件を満たしており、表の8件は主に収束状態の制約による。基準の解がすべて低品質だったという意味ではない。

設定を厳しくすることによる利益・不利益も分けて確認できた。

| 変更する係数だけを変えた比較 | その他の条件 | 観測結果 |
| --- | --- | --- |
| β：`8e-7 → 8e-12` | 既定 float、rtol=`8e-7`, vtol=`3.2e-6`, μ=`1e-6`, η=`5e-3` | 品質22/22は同じ。ベクトル収束4→16/16、内部失敗12→0 |
| η：`5e-3 → 1e-6` | 既定、β=`8e-12`, rtol=`8e-7`, vtol=`3.2e-6`, μ=`3e-4` | 品質22/22は同じ。ベクトル収束は float 16→14/16、double 16→15/16 |

分離して設定できることは、係数間の数値的な相互作用がなくなることを意味しない。特に小さいシフトは求解を難しくし、内側 GMRES への過度に厳しい要求は、外側の固有対が十分正しくても全体の成功判定を妨げる場合がある。

ホスト std double では、候補 B `(β,rtol,vtol,μ,η)=(8e-12,8e-12,3.2e-10,1e-11,5e-3)` が高精度ゲート `1e-10` を22/22件で満たし、収束も全件成立した。最大固有値誤差は `2.30205e-13`、最大固有対残差は `2.80476e-11`。この条件では μ を `1e-9` から `1e-11` へ小さくする利益があった。数学関数・型の精度が異なる条件へ候補をそのまま移せるとは限らない。

## 6. 定数パラメータにする方法と試作の検証

最小の設計は、セクション2の5個の名前付き定数を定義し、現在の `epsilon()` 由来の値を置き換える方法である。既存の公開メンバーによる上書きは維持できる。値を保存するインスタンスメンバーを増やす必要はない。

同じプログラム内で「単独 GMRES と逆反復内の GMRES に異なる β」を使いたい場合は、βを持つ設定型をテンプレート引数として渡す設計も可能である。C++11 では浮動小数点値を非型テンプレート引数にはできないため、`static constexpr double` を持つ設定型を使い、固有値ソルバから内部 GMRES へ渡す。これには API の拡張が必要だが、インスタンスの RAM を増やさずに設定を分けられる。設定ごとにインスタンス化されるためコード容量が増える可能性がある。今回検証したのは最小の定数置換方式であり、この設定型方式の実装は行っていない。

βは非負に制約する。β=0でもゼロ長の探索方向を breakdown と判定する条件を維持する必要がある。負のβはこの判定をすり抜けてゼロ長ベクトルの正規化へ進む可能性があるため、固定定数なら `static_assert` で禁止できる。`division_min` と、逆数の表現範囲を扱う `numeric_limits<T>::min()` の保護は維持する。

候補 A を名前付き `constexpr double` の設定にして、GMRES のβ、固有値・固有ベクトルの既定許容誤差、シフト既定値、内部 GMRES の未指定時の許容誤差を一時コピー上で置換した。シフトの `sqrt(epsilon)` 下限も除き、Eigen ヘッダで不要になった `<limits>` を一時コピー内だけで削除した。

| 既存試験 | template 構成 | for 構成 |
| --- | --- | --- |
| `gmres_regression.cpp` | 失敗0 | 失敗0 |
| `eigen_regression.cpp` | 失敗0 | 失敗0 |
| `constraints_regression.cpp` | 動的確保0、禁止 `<cmath>` でビルド成功 | 動的確保0、禁止 `<cmath>` でビルド成功 |

試験の assert・許容誤差は変更していない。制約監視は `-fno-exceptions` も指定した。候補探索とは別の既存回帰ケースで確認しているが、今回の全パラメータ組合せをこの6実行で検証したという意味ではない。

## 7. 反復上限・RAM・調査の範囲

- 全672件の単独 GMRES は反復数が N 以下。小さいβで早期停止を避ける場合でも、今回の `K=N, cycles=1` の上限は変わらない。
- 全11,616件の固有値出力・品質指標は有限で、一般 QR の各ケースは128 sweep 以下だった。収束条件を厳しくすると上限まで処理が続く場合がある。
- 固有値ソルバの `sizeof` は全設定で一定だった。float は real 176 B / complex 264 B / Jacobi 88 B、double は296 B / 464 B / 168 B。GMRES も同じ型・サイズでは一定だった。
- GMRES の代表構成（β=`8e-16`、既定数学）では、for 版112行が template 版と完全一致した。
- 実時間、ピークスタック、逆反復・内部 GMRES の総仕事量は測定していない。QR sweep 合計だけで全体の高速化は主張できない。
- 固有ベクトルの成分一致、正規直交性、重複固有値の固有空間全体の階数は今回の品質ゲートに含めていない。固有対の残差を評価した。

固定値を選ぶ際は、要求する解誤差を先に決め、その基準を変えずに収束状態・反復数を比較するとよい。今回の結果は、機械 epsilon との連動を外して用途別に調整する運用を支持するが、すべての係数を小さくすれば改善するという結果ではない。

## 9. 固定パラメータの採用（2026-11-17）

既定の数学ライブラリを使う float・double の両方で品質と収束を確認した候補Aを、本体の既定値として採用した。型や数学ライブラリのマクロによる自動切替は行わず、各係数を独立した名前付き定数として定義した。

| 定数 | 採用値 | 定義ファイル |
| --- | --- | --- |
| `GMRES_BREAKDOWN_RELATIVE_TOLERANCE` | `8.0e-12` | `base_matrix_gmres.hpp` |
| `DEFAULT_RELATIVE_TOLERANCE_EIGEN_SOLVER` | `8.0e-9` | `base_matrix_eigen_solver.hpp` |
| `DEFAULT_EIGENVECTOR_RELATIVE_TOLERANCE` | `3.2e-6` | 同上 |
| `DEFAULT_EIGENVECTOR_RELATIVE_SHIFT` | `3.0e-4` | 同上 |
| `DEFAULT_INNER_GMRES_RELATIVE_TOLERANCE` | `5.0e-3` | 同上 |

一般固有値・対称 Jacobi の相対許容誤差を同じ定数から初期化する。逆反復シフトの `sqrt(epsilon)` による下限を除去し、`gmres_k_decay_rate <= 0` の場合も固定の内側許容誤差を使う。正の値を指定した場合の上書き動作は維持する。単独 GMRES の相対・絶対許容誤差の既定値は0のままである。

従来の `EIGEN_SMALL_VALUE` は、ソース互換性のため `DEFAULT_EIGENVECTOR_RELATIVE_SHIFT` を参照する定数として残した。従来の値 `1e-6` は `3e-4` に変わる。4個の `*_EPSILON_MULTIPLIER` 定数は役割が変わるため削除し、上表の直接指定する相対係数へ置き換えた。

`division_min` とシフトの分母保護、`numeric_limits<T>::min()` による逆数の表現範囲の保護は維持した。βには非負の `static_assert` を追加し、ゼロ長の探索方向が正規化されることを防ぐ条件を維持する。新しいインスタンスメンバーはなく、反復回数の上限も変更していない。Eigen ヘッダで不要になった `<limits>` を削除し、GMRES 側は `min()` に必要なため残した。

### 高精度を要求する場合

今回の既定値は、標準数学ライブラリの double で従来の機械epsilon相当の精度を自動的に要求する設定ではない。セクション5の候補Bなど、必要な精度に応じて公開メンバーを明示指定する。例えば候補Bを使う場合は、一般固有値ソルバに次のように設定できる。

```cpp
solver.relative_tolerance = static_cast<T>(8.0e-12);
solver.eigenvector_tolerance = static_cast<T>(3.2e-10);
solver.set_small_value(static_cast<T>(1.0e-11));
solver.set_gmres_k_decay_rate(static_cast<T>(5.0e-3));
```

これらは調査ケースでの高精度設定例であり、全入力の誤差上限を保証するものではない。より厳しい精度基準を持つ既存回帰試験では、基準自体を緩めず、精度に対応する設定を明示して検証する。既定値での品質・収束も別の試験で確認する。

### 採用後の検証

現在の作業ツリーを直接検証する runner を追加した。過去の調査 runner は比較対象 commit を固定しているため、そのまま保存した。

```sh
python3 test_vs/algorithm_improvements/run_fixed_parameter_validation.py \
  --output /tmp/fixed_parameter_validation --legacy-configs --sanitize
```

数値回帰はC++11、既定数学・ホスト標準数学、template・forの両経路で行う。制約監視は `<cmath>` 禁止、例外無効、動的確保の監視を含む。`--legacy-configs` は既存CIの8構成、`--sanitize` はGMRES・Eigenのアドレス・未定義動作・浮動小数点ゼロ除算の検査を追加する。
