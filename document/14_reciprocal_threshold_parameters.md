# 逆数を使用する下限値の定数化

更新日：2026-11-17

## 1. 採用した変更

**`std::numeric_limits<T>::min()`を使っていた6箇所を、既定値`1e-30`の名前付き定数へ置き換えた。** いずれもヘッダ先頭の`constexpr double`として定義し、使用時に`T`または複素数の実数成分型`Real`へ変換する。

| ファイル | 定数 | 既定値 | 用途 |
| --- | --- | ---: | --- |
| [LU](../base_matrix/base_matrix_lu_decomposition.hpp) | `RECIPROCAL_MIN_LU_DECOMPOSITION` | `1e-30` | 対角逆数の生成・キャッシュを使う下限。2箇所で使用 |
| [Cholesky](../base_matrix/base_matrix_cholesky_decomposition.hpp) | `RECIPROCAL_MIN_CHOLESKY` | `1e-30` | `SPDLDLT`で対角逆数を使う下限 |
| [GMRES](../base_matrix/base_matrix_gmres.hpp) | `NORMALIZATION_RECIPROCAL_MIN_GMRES` | `1e-30` | 初期残差と次の基底ベクトルの正規化で逆数を使う下限 |
| 同上 | `PRECONDITIONER_RECIPROCAL_MIN_GMRES` | `1e-30` | `gmres_inverse_diagonal`で対角逆数を採用する下限 |

例えばLUでは次の定数を編集して再ビルドすればよい。クラスの実行時メンバーは増やしていない。

```cpp
constexpr double RECIPROCAL_MIN_LU_DECOMPOSITION = 1.0e-30;
```

既存の`division_min`、相対ピボットしきい値、収束許容誤差、GMRESのbreakdown係数は別のパラメータとして維持した。3ヘッダで不要になった`#include <limits>`も削除した。

## 2. なぜ`min()`でなくてもよいか

浮動小数点型の`numeric_limits<T>::min()`は、非正規化数を持つ型では「正の最小の正規化数」を返す。機械イプシロンや収束許容誤差とは異なる。[C++標準ドラフトの定義](https://eel.is/c++draft/numeric.limits.members)

一般的なIEEE 754のfloatでは約`1.175e-38`、doubleでは約`2.225e-308`である。従来の6箇所は、この値を**先に`1 / denominator`を作ってよいかの判定**に使っていた。

例えば、分子・分母がどちらも非常に小さい場合、`numerator / denominator`は有限でも、先に`1 / denominator`を作るとオーバーフローすることがある。そのため、小さい分母では逆数の共用をやめる、という役割だった。

この切替に最小正規化数そのものを使う必要はない。`1e-30`なら、その逆数は約`1e30`で、今回対象のfloat/doubleの両方で表現できる。従来より広い範囲を直接除算へ回す設定となる。

## 3. しきい値を変えると何が変わるか

### LU・SPDLDLT・GMRESの正規化

| 分母の大きさ | 処理 |
| --- | --- |
| 定数以上 | 逆数を一度作り、掛け算に共用する |
| 定数未満の非ゼロ値 | 逆数を作らず、各成分を直接除算する |

**定数未満の値をゼロにしたり、この定数を理由にピボットを棄却したりはしない。** 元からあるピボット判定や、正規化前の非ゼロ判定を通った後の計算方法を切り替える。

`a / b`と`a * (1 / b)`には丸めの違いがあるため、結果のbit一致や、その後の収束状態が全入力で同じになる保証はない。定数を大きくすると直接除算が増え、実行時間が増える場合もある。定数を小さくすると逆数を共用する範囲が広がるが、型で表現できる範囲を越えてはならない。

通常のLU・SPDLDLTでは、既定の`division_min=1e-10`が先に適用される。この既定値のままなら、受け入れたピボットは新しい`1e-30`も上回る。変更の影響が出るのは主に、`division_min`をさらに小さく設定する使い方である。GMRESのノルム正規化はこのピボット判定とは別なので、小さい右辺でも切替が起こり得る。

### GMRESの対角前処理

`gmres_inverse_diagonal`では、対角の大きさが`division_min`または`PRECONDITIONER_RECIPROCAL_MIN_GMRES`未満なら、該当する前処理成分を`1`にする。逆数が表現できない場合にも前処理を安全に省略するための既存動作である。

この用途だけは、定数を大きくすると**前処理自体が変わる**。例えば実数対角`1e-32`、`division_min=1e-37`なら、従来は約`1e32`を返すが、新しい既定値では`1`を返す。前処理を用いた求解の収束や時間にも影響し得るため、正規化用の定数と分離した。

実際に`A=diag(2e-32,3e-32)`、真値`[1,2]`を与えた追加試験では、float/doubleとも、旧設定で1反復、新しい`1e-30`で2反復になった。いずれも既知解の精度基準を満たした。候補`1e-35`・`1e-37`では対角逆数が採用され、1反復に戻った。このような極小対角の前処理を使う場合は、前処理用定数を小さくする選択肢がある。

## 4. 他の小さい固定値を設定する場合

float/double共用では、例えば`1e-32`、`1e-35`、`1e-37`も候補にできる。

| 設定値 | 今回のfloatでの性質 | 運用上の意味 |
| --- | --- | --- |
| `1e-20` | 値・逆数とも表現可能 | `1e-30`より広い範囲を直接除算／単位前処理にする |
| **`1e-30`** | 値・逆数とも正規化数として表現可能 | 今回の既定値 |
| `1e-32`・`1e-35`・`1e-37` | 値・逆数とも正規化数として表現可能 | より小さい値まで逆数を共用する候補 |
| `1e-38` | 分母側が非正規化数になる | 非正規化数をゼロ扱いする実行環境への依存があるため、共用設定としては推奨しない |
| `1e-40` | 逆数がfloatの表現範囲を超える | float/double共用設定には使用しない |
| `1e-300` | floatへの変換時に0になる | 同上。double単独なら事情が異なるが、今回の共用設定では許可しない |

float/double共用では**`1e-37`以上の正の値を候補とし、まず`1e-30`から調整する**。これは今回の型を前提とした推奨範囲で、あらゆる数値型・マイコンの動作モードを保証する値ではない。

設定値が不適切なときに実行時の問題へ持ち込まないよう、ヘッダにはコンパイル時検査を追加した。狭い型であるfloatへの変換後に正であり、逆数も正値として定数評価できることを確認する。実行時の除算やメモリ領域は追加しない。

```cpp
static_assert(static_cast<float>(RECIPROCAL_MIN_CHOLESKY) > 0.0f &&
                  1.0f / static_cast<float>(RECIPROCAL_MIN_CHOLESKY) > 0.0f,
              "The Cholesky reciprocal threshold must have a positive, "
              "representable float reciprocal.");
```

この検査だけでは、実行環境が非正規化数をどう扱うかまでは判定しない。入力・出力の非有限値の確認を利用側が行う方針も維持している。

## 5. 検証

GCC 15.2.0・C++11で、以下を確認した。既存試験のassertは変更していない。

| 検証 | 結果 |
| --- | --- |
| 既存のGMRES・固有値・LU/Cholesky・制約検査・8種のlegacyビルドなど | **29実行成功** |
| 旧min判定と固定値、TMP/for、既定/標準数学、追加の極小入力・sanitizer | **13実行成功** |
| 各定数を0または`1e-40`へ変更した不適切設定 | **8構成すべてコンパイル時に拒否** |

追加試験では、float/double、負のLUピボット、LUキャッシュ有無、実数・複素数GMRES、ゼロ入力を確認した。通常のスケールから`1e-37`までに加え、float `1e-39`、double `1e-100`・`4e-310`も対象とした。直接除算で有効な小さいピボットを扱えること、既知解を得られること、ゼロ除算・オーバーフロー・不正演算の例外フラグが出ないことを確認した。

固定値の候補`1e-20`・`1e-35`・`1e-37`も同じ追加試験を通過した。これらは安全に設定できる例の確認であり、全入力について最適な定数を選ぶ比較ではない。

詳細は[追加試験・再実行手順](../test_vs/algorithm_improvements/results/reciprocal_threshold_parameters/README.md)と[既存29実行の記録](../test_vs/algorithm_improvements/results/reciprocal_threshold_parameters/existing_regressions/README.md)を参照。

これは定数化による動作の検証であり、マイコンでの時間測定や、全入力での数値同値性の証明ではない。
